# 여행 탭 화면 명세

> 여행 탭(구 플랜)의 구성 요소·수치·상태 전이 조회표. 전환 배경은
> [ADR 0009](../adr/0009-travel-tab-conversational-agent.md), 조건 시트 폐기와
> 조회 축 교체는 [ADR 0010](../adr/0010-travel-tab-drops-condition-sheet.md),
> 실제 지도·카드 탭·완화 칩 폐기는
> [ADR 0012](../adr/0012-travel-tab-live-map-and-card-tap.md).
> 색·간격 정본은 `mobile/src/constants/theme.ts`.

탭은 홈 · 탐색 · **여행** · 마이 4개. 여행 탭만 이 문서의 범위다.

## 화면 구조

`src/app/(tabs)/travel.tsx` 한 화면 안에 3층이 쌓인다.

| 층 | 내용 | 비고 |
|---|---|---|
| 상단 바 | 워드마크 `PICTRIP` **가운데 정렬**(절대 배치) + 우상단 `새 대화` | 하단 1px `line` |
| 스크롤 | 대화 (턴이 없으면 인사말) | 대화가 아래로 이어붙는 단일 스크롤 |
| 도크 | 칩 행 + 컴포저 | 탭바 위 1층 고정, 배경 `bg` + 상단 1px `line`, **빈 상태에도 그대로** |

채널 보드는 폐기됐다 — 홈 탭 `ChannelTiles`와 중복이었다. 여행 탭은 조용한
챗봇 한 표면이다. 사진 진입은 **컴포저 안 아이콘 두 개(앨범·촬영)뿐**이다 —
빈 화면의 `사진으로 찾기` CTA는 폐기했다. 첫 화면은 인사말과 도크만 남는다.

### 도크 칩

칩은 상태마다 다른 물건이다 ([ADR 0011](../adr/0011-travel-tab-chip-state-machine.md)).
표시 우선순위는 **앵커 > refine > 초기**이며 한 순간에 한 종류만 보인다.

| 상태 | 칩 | 종류 | Gemini |
|---|---|---|---|
| t=0 · 좌표 O | `근처 맛집` · `근처 볼거리` · `근처 카페` · `지금 축제` | anchor · intent | ❌ |
| t=0 · 좌표 X | `지금 축제` · `사람 적은 바닷가` · `비 와도 갈 만한 실내` · `제주에서 한적한 곳` | intent · question | 축제만 ❌ |
| t=1 결과 | `사람 적은 곳만`/`유명한 곳으로` · `실내만`(실내 결과가 있을 때만) · `가까운 순으로` | refine, 최대 3개 | ❌ |
| t=2 앵커 | `근처 맛집` · `근처 카페` · `주변 볼거리` · `오늘 붐벼?`(`hasCrowd`일 때만) | anchor | ❌ |

`근처 볼거리`만 앵커가 아니라 `intent{nearMe}` 다 — 앵커의 attraction 술어는
지도 탭용이라 박물관·전시관·공연장을 뺀다.

`새 대화`는 턴이 있을 때만 그린다(h32, radius 16, 1px `line`, 13/700 `sec`).
탭하면 `conversation-store`의 `clear()` + 로컬 초안·첨부·앵커를 비운다.

### 빈 상태

스크롤 영역을 덮는 절대 배치 오버레이라 도크·칩은 움직이지 않는다.
빈 상태에서만 `pointerEvents: box-none` — 인사말·마스코트는 탭을 흘려보내고
시작 액션만 터치를 받는다. 대화가 시작되면 오버레이가 통째로 `none` 이 된다.
`box-none` 은 부모만 히트 테스트에서 빼고 자식은 `auto` 로 남기므로, 투명해진
인사말이 아래 대화의 탭을 가로채지 않으려면 `none` 이어야 한다.
접근성은 `accessibilityElementsHidden` 이 따로 막는다.

| 요소 | 값 |
|---|---|
| 마스코트 | `Mascot` 60px `ink`, 아래 여백 16 |
| 인사말 | `오늘,\n어디로 갈까요` 26/800, letterSpacing -0.9, lineHeight 34, 중앙 정렬 |
| 전이 | 첫 턴이 생기면 opacity 180ms 페이드 |

`Mascot`(`features/travel/components/Mascot.tsx`) = `react-native-svg` 단선
졸라맨. viewBox `0 0 64 64`, `strokeWidth = (size / 60) * 2.6`,
`strokeLinecap/join: round`. 4.2초 주기 ±4px `translateY` 부유
(`useNativeDriver`, 빈 상태에서만 재생). 액자 안 해(circle)는 두지 않는다 —
획 두께가 크기에 비례해 확대해도 뭉개짐이 그대로다.

### 스팟 카드

사진 위에 캡션을 얹는 홈 `PostSlide` 문법. 값은 실측 기준이며 실기기에서
1.9장 걸침이 "더 있다" 신호로 약하면 170px(2장 딱 떨어짐)로 조정한다.

| 요소 | 값 |
|---|---|
| 크기 | 대화 결과 레일 168×190 (이미지 150 + 소개 40), radius 16 |
| 이미지 | `cover`, 배경 `skeleton`, 로드 실패 시 opacity 0 |
| scrim | `linear-gradient(180deg, rgba(20,18,22,.16) 0%, transparent 32%, transparent 46%, rgba(16,14,18,.80) 100%)` + inset 1px `line` |
| 상태 태그 | 좌상단 9/9, h24, radius 999, 배경 `control` + blur 8, 11/800 `onImage` |
| 하트 | 우상단 9/9, 28×28, 배경 `control` + blur 8, 활성 시 `danger` + fill |
| 캡션 | 좌우 12 / 하단 12, 제목 14.5/800 `onImage` 1줄, 지역 11.5 `onDim` 1줄 |
| 탭 | 한 번 = 앵커 토글(빨간 링, 나머지 딤), 두 번 = 상세, 하트 → 저장 토글 + 토스트 (`scale(.975)` 프레스) |

이미지 URL은 백엔드가 서명한 `img.pictrip.org` 프록시 URL을 **그대로** 통과시킨다
(`cpyrhtDivCd=Type3`는 무변형 pass-through — [ADR 0005](../adr/0005-kto-image-policy.md)).

## 대화

스크롤 영역 전체가 대화다(좌우 20, 상단 22). 각 턴은 아래 순서로 쌓인다.

| 순서 | 요소 | 사양 |
|---|---|---|
| 1 | 사용자 버블 | 우측 정렬, 배경 `ink` / `onImage`, radius 14, padding 11/14, 최대 폭 80%. 사진 첨부 시 버블 위에 104px 썸네일 |
| 2 | 조회 단계 카드 | 1px `line` 박스 radius 16 padding 16. 행마다 스피너 → 체크(`accentText`), 우측에 개수 배지 11/700 `accentText` on `accentFill` |
| 3 | 답변 문장 | 14.5/1.55, 숫자·핵심어는 `<b>` = `accentText` 800 |
| 4 | 지도 카드 | 좌표가 있는 결과가 1곳 이상일 때만. **실제 Kakao 지도**(200px, 최신 턴만) + 공간 요약 한 줄 + `지도에서 보기` |
| 5 | 결과 레일 | 응답 스팟 **전체**를 담는 가로 `FlatList`(가상화). 카드 168×190 — 이미지 150 + 소개 40. 한 번 탭 = 앵커, 두 번 탭 = 상세 |
| 6 | 기준 줄 | `tagBasis` — 카드 태그가 무엇을 잰 값인지. 서버가 안 주면 그리지 않는다 |
| 7 | 푸터 | 카드 탭 안내 문구 11.5 `ter` |

- 턴 등장 = `translateY(9px)` + opacity, 0.32s `cubic-bezier(.2,.7,.3,1)`.
- 단계는 **재생하지 않는다**. 대기 중에는 그 요청이 실제로 밟을 단계를
  스피너로 세워두고(`pendingSteps`), 응답이 오면 서버가 실행한 단계로
  즉시 교체하며 답변·레일을 같은 프레임에 붙인다. 인위적 지연은 없다.
- 대기 단계는 요청 모양이 정한다 — 자유문(의도 추출 있음)은
  `질문에서 조건 읽는 중` + `여행지 찾는 중`, `intent`·`anchor` 직송은
  `여행지 찾는 중` 하나. 서버가 Gemini를 타지 않는 경로를 그리지 않는다.
- 응답 대기 중에는 새 질의를 받지 않는다(도크 전송 비활성).
- **자유문 후속 질문은 직전 턴을 싣는다.** 마지막으로 답이 온 턴의 `intent` 와
  결과 제목 8개를 `context` 로 보낸다. 앵커 칩을 탭해야만 이어지던 것이 말로도
  된다 — `거기 근처 카페는?` 이 동작한다. 첫 질문에는 싣지 않는다.
- **카드 소개 줄은 `spot_details.overview` 의 첫 문장을 그대로 쓴다.**
  overview 는 원문 그대로 보관·노출이 원칙이므로 **서버는 원문의 연속된
  조각(첫 문장)을 그대로 보낸다** — 태그 제거도, 공백 접기도, 말줄임표 추가도
  하지 않는다. 잘라내기는 카드가 `numberOfLines={2}` 로 하고 `…` 도 RN 이
  붙인다. 표시 사정 때문에 원문에 없는 글자를 서버가 만들지 않는다.
  태그가 섞인 overview 는 아예 쓰지 않는다(지우면 원문과 달라지고, 두면 `<br>`
  이 보인다). 소개가 없는 카드도
  같은 높이를 유지해 레일이 들쭉날쭉해지지 않는다.
  **캐시가 낡았으면 아예 안 쓴다** — `spots.modified_time` 이 `spot_details.cached_at`
  보다 새로우면 그 스팟은 소개를 비운다. 낡은 설명을 지금 설명인 척 보여주는
  것보다 비는 편이 낫다.
- **기준 줄은 조직명을 적지 않는다.** 출처 표기는 마이 > 데이터 출처 문서가
  맡는다. 여기서는 무엇을 잰 값인지만 말한다 — `혼잡도 8/3 예측 기준`,
  `현재 위치에서 직선거리`, `사진과의 CLIP 벡터 유사도`. 태그 종류는 응답마다
  균일하므로 카드가 아니라 응답 단위로 한 줄이다.
  **날짜는 결과가 전부 같은 날일 때만 적는다.** 집중률 동기화는 매칭된
  `content_id` 만 upsert 하고 빠진 행을 지우지 않아 한 응답에 다른 날짜가 섞일
  수 있다. 섞이면 날짜 없이 `혼잡도 예측 기준` 만 말한다.
- **빈 화면에는 CTA 를 두지 않는다.** 마스코트·인사말 아래에는 위치 프라이머
  한 줄만 남는다(권한이 `undetermined` 일 때만). `사진으로 찾기` 큰 버튼은
  컴포저의 앨범·촬영 아이콘과 같은 일을 두 번 시키는 물건이라 지웠다.
- **위치 프라이머는 `undetermined` 일 때만 뜬다.** 거절한 사용자에게 다시 묻지
  않고, 이미 허용한 사용자에게는 아예 안 보인다. 이전에는 권한을 **요청조차
  하지 않아** 신규 사용자가 `내 근처` 를 영영 못 봤다.
- **사진 턴은 원본과 1순위 매칭을 나란히 그린다.** 유사도 숫자만으로는 결과가
  이상할 때 내 사진 탓인지 모델 탓인지 알 수 없다. 무엇을 보고 닮았다 했는지는
  **적지 않는다** — CLIP 은 벡터를 주지 벡터에 이름을 주지 않으므로 속성을
  적으면 지어내는 것이 된다.
- **턴 안의 지도는 실제 Kakao 지도지만, 살아 있는 건 최신 턴 하나뿐이다.**
  턴마다 `KakaoWebMap` 을 두면 WebView 와 SDK 로드가 N개가 된다. 그래서 좌표가
  있는 **가장 최근 턴만** 지도를 마운트하고(`live`), 지나간 턴은 같은 카드에서
  요약 줄 + `지도에서 보기` 만 남긴다. 스크롤을 아래에 두고 대화하는 동안에는
  항상 지도가 보이고, 위로 올려 본 옛 턴은 요약만 보인다.
- **결과가 전국에 흩어지면 턴 지도는 가장 많은 지역만 잡는다.** 200px 높이에서
  Kakao 최소 축척으로 담을 수 있는 세로 폭은 약 300km 라, 고성~제주처럼 위도
  차가 2.5°를 넘으면 전체를 맞추려다 **핀이 하나도 안 보이는 빈 지도**가 됐다.
  그래서 `miniFitSpots` 가 위도 폭을 재고, 넘치면 같은 `regionLabel` 이 가장 많은
  묶음에 맞춘다. 핀은 그래도 **전부** 올린다 — 카드를 탭하면 그 좌표로 옮겨 가고,
  전체 분포는 요약 줄과 `지도에서 보기` 가 맡는다.
- **턴 지도의 핀은 빨강(`accent`)이다.** 지도 탭의 잉크 핀과 달리 이 지도는
  "방금 찾은 결과"만 담기 때문에 핀 전부가 결과다. 카드를 한 번 탭해 앵커를
  잡으면 그 핀이 라벨 달린 큰 핀이 되고 지도가 그 좌표로 이동한다 —
  카드와 지도가 같은 선택 상태(`anchorSpot`)를 읽는다.
- **`지도에서 보기` 는 모달이 아니라 라우트다**(`/travel-map`). 모달 안에서는
  상세로 가려면 모달을 닫아야 해서 **뒤로 가기가 지도가 아니라 대화로**
  떨어졌고, `SafeAreaView` 인셋이 첫 프레임에 0이라 닫기 버튼이 노치에 잘렸다.
  스택 라우트로 올리면 대화 → 지도 → 상세 → 뒤로 = 지도가 그대로 성립하고,
  인셋은 `useSafeAreaInsets()` 로 첫 프레임부터 정확하다. 지도에 실을 스팟·질문·
  선택은 `features/travel/stores/map-store.ts` 가 들고 있다.
- 공간 요약은 좌표에서 계산한다 — 시군구별 개수(`제주시 2곳 · 서귀포시 1곳`)와,
  가장 먼 두 곳이 20km 이상이면 그 거리. 동선이 하루에 되는지를 카드 목록만
  보고는 알 수 없기 때문이다.
- 지도 화면은 열 때마다 그 턴의 스팟으로 스토어를 덮어쓴다(`open()`). 선택 핀
  상태가 이전 턴에서 넘어오지 않는다.
- 후속 칩은 턴 안에 그리지 않는다 — 마지막 답변의 `refinements`가 **도크
  칩으로만** 뜬다.

## 도크

위에서부터 앵커 배너 → 첨부 배너 → 칩 행 → 컴포저. 턴이 0개여도 그대로 그린다
— 빈 상태 전용 렌더 분기가 없어 키보드가 올라와도 레이아웃이 흔들리지 않는다.

컴포저는 pill이 아니라 **rounded-rect**다. 입력 줄 아래에 액션 행을 두기
위해서다.

| 요소 | 사양 |
|---|---|
| 칩 행 | 마지막 답변의 후속 칩, 없으면 초기 칩 (`composerChips`) |
| 칩 공통 | h34, padding 0/16, radius 999, 1px `line`, 13.5/700 `sec`, gap 8, 가로 스크롤 |
| 컴포저 | 배경 `inset` + 1px `line`, **radius 24**, padding 12/12/10, margin 4/20/14 |
| 입력 | 14.5/500 한 줄, placeholder `사진을 올리거나 물어보세요` (첨부 시 `사진에 덧붙일 말 (선택)`) |
| 액션 행 | 입력 아래 marginTop 10, 좌측 그룹(gap 8) + 우측 전송 |
| 촬영 버튼 | 36×36 radius 18, 1px `rgba(230,0,35,0.32)`, `camera` 아이콘 17 `accent`. 액션 행 맨 왼쪽 |
| 앨범 버튼 | 같은 사양, `image` 아이콘. **둘 다 라벨 없음, 배경 채우지 않음** |
| `내 근처` | h36 radius 18, 1px `line`, `location` 15 + 13/700 `sec`. 좌표가 없으면 렌더하지 않는다 |
| 전송 | 36×36, 기본 `control`, 입력 또는 첨부가 있으면 `ink` |
| 첨부 배너 | 컴포저 위, `accentFill` + 1px `rgba(230,0,35,.24)`, 38px 썸네일 + "사진 1장 첨부됨 / 서버에 저장하지 않고 비교 후 폐기해요" |

사진 강조는 카피가 아니라 **placeholder + 아이콘 틴트**로만 한다. 안내 문구는
읽히지 않지만 placeholder는 커서 옆이라 반드시 읽히고, 틴트는 면적을 늘리지
않으면서 회색 일색인 컴포저에서 유일한 색이 된다. `colors.accent`가 저장(하트)·
앵커 링과 의미가 겹치는 것은 "이 앱의 주요 행동"으로 묶어 감수한다.

앨범 버튼 = `pickTravelPhoto()`, 촬영 버튼 = `shootTravelPhoto()`. 둘 다
**첨부만** 한다(전송은 별도). 액션시트가 아니라 버튼 두 개인 이유는
`ActionSheetIOS`가 iOS 전용이고 `Alert`로 대체하면 탭이 두 번이 되기 때문이다.

실패 토스트는 권한 종류가 달라 분리한다 — 앨범은 `사진을 불러오지 못했어요…`,
촬영은 `카메라를 열지 못했어요…`. 촬영은 `requestCameraPermissionsAsync()`가
거부되면 카메라를 열지 않고 토스트 경로로 보낸다.

첨부만 있고 텍스트가 없으면 **버블 문구만** `이 사진 같은 분위기의 여행지`로
채운다. 서버에는 질문 필드가 아예 실리지 않아 Gemini 호출이 없다.

## 칩

칩은 두 종류다(`lib/chips.ts`). 정형 조건 시트는 폐기됐다
([ADR 0010](../adr/0010-travel-tab-drops-condition-sheet.md)).

```ts
type Chip =
  | { kind: "question"; label: string; question: string }
  | { kind: "refine"; label: string; patch: RefinePatch };
```

**초기 칩** — 클라이언트 상수. 전부 실측으로 모수가 확인된 것만 둔다.

| 칩 = 질문 문자열 | 근거 모수 |
|---|---|
| `지금 열리는 축제` | 오늘 진행 56건 (대표이미지 보유) |
| `사람 적은 바닷가` | mood `sea` 763곳 (rated 530) |
| `비 와도 갈 만한 실내` | VE06+VE07 1,906곳 |
| `제주에서 한적한 곳` | 제주 rated 264곳 |

거리 질의(`여기서 가까운 곳`)는 칩 레일이 아니라 컴포저 액션 행의 `내 근처`
pill이다(`NEARBY_CHIP`) — 후속 칩·앵커 칩이 레일을 차지해도 항상 닿는다.

지역은 시트가 아니라 **질문 문자열에 실어** 보낸다 — 서버의 `regionHints`
경로가 그대로 처리한다. `사람 적은 곳` 단독 칩은 두지 않는다. `숨은 관광지`
레일과 결과가 겹쳐서, 혼잡도 축에는 항상 다른 축을 하나 더 붙인다.

**후속 칩** — 서버 `refinements[]`(`{label, patch}`)를 **도크에서만** 그린다.
빈 배열의 뜻은 `totalCount`가 가른다: 결과가 있는 턴에서 비면 초기 칩으로
되돌아가고(백엔드가 앱보다 구버전인 경우 포함), **0곳 턴에서 비면 칩을 아예
안 낸다** — 되짚을 조건이 있는데 넓힐 지역이 없는 상태라, 여기서 `지금 축제`
같은 초기 칩을 내면 방금 실패한 조건과 무관한 제안이 답변 밑에 붙는다.
파생 규칙과 우선순위는 서버 소유라 [api](api.md#post-agentask)에 있다. 탭하면
**마지막 답변 턴**의 `intent` + 그 칩의 `patch`를 보낸다 — 질문 문자열을
합성하지 않으므로 `여수 바다`에서 `사람 적은 곳만`을 눌러도 여수를 잃지
않는다. 과거 턴을 골라 정제하는 경로는 없다.

사진 턴의 후속 칩은 **같은 사진을 다시 첨부해** 재요청한다. 벡터가 필요해
intent 왕복만으로는 재실행할 수 없고, `Turn`이 이미 `photo`를 들고 있다.
업로드가 1회 더 들지만 동작이 정직하다.

## 앵커 후속 질문

대화 레일 카드를 탭하면 그 스팟이 **앵커**가 된다. 선택 상태는 화면 로컬
(`travel.tsx`의 `anchorSpot`)이고 서버 왕복이 없다.

| 요소 | 사양 |
|---|---|
| 선택 표시 | 선택 카드에 2.5px `accent` 링, 같은 레일의 나머지 카드 opacity 0.55, 턴 지도의 해당 핀이 라벨 달린 큰 빨간 핀 |
| 컨텍스트 필 | 독 상단에 장소명 + `×`(해제), `accentFill` 배경 + `accentText`, 우측에 "이 장소 기준으로 물어봐요" 안내 |
| 앵커 칩 | `근처 맛집`(food) · `근처 카페`(cafe) · `주변 볼거리`(nearby) · `오늘 붐벼?`(crowd) — refine 칩 대신 노출 |

- 앵커 칩 탭 = `/agent/ask`에 `anchor: {contentId, action}`만 보내는 새 턴.
  버블 문구는 `"{장소명} {칩 라벨}"`, `Turn.anchor`로 재시도까지 재현된다.
- **앵커는 카드 한 번 탭, 상세는 두 번 탭이다.** 전용 `여기 기준으로` 버튼은
  지웠다 — 카드마다 34px 줄이 붙어 레일이 무거웠고, 이어 묻기가 상세보다 훨씬
  잦은 동작인데 더 작은 표적이었다. 판정은 `useCardTap`(260ms) 이 한다: 260ms
  안에 같은 카드가 다시 눌리면 상세, 아니면 앵커 토글. 첫 탭의 `onPressIn` 이
  이미 상세를 프리페치해 두 번째 탭이 늦게 열리지 않는다.
- **스크린 리더에서는 상세가 커스텀 액션이다.** VoiceOver·TalkBack은 사용자의
  두 번 탭을 활성화 한 번으로 바꿔 보내 `onPress`가 한 번만 오고, 그러면 항상
  앵커 토글만 걸린다. 카드에 `상세 보기` 접근성 액션(`SpotCard`의
  `accessibilityActions`)을 달아 로터/액션 메뉴로 상세에 닿게 한다.
- 선택 해제 조건: 같은 카드 한 번 탭, `×` 탭, 다른 카드 앵커(교체), **자유 입력
  시작**, 사진 첨부, 새 자유문 질의 전송. 자유 입력은 앵커를 싣지 않으므로
  입력이 시작되는 즉시 선택 UI를 내린다.
- `crowd` 응답은 `spots`가 빈 답변 전용 턴 — 레일 없이 답변 문장만 그린다.
  문구는 `spot_concentration` 일일 예측의 범위를 넘지 않는다("오늘 혼잡도
  예측은 … 수준").

## 상태

| 상황 | 처리 |
|---|---|
| 위치 권한 없음 | `내 근처` pill을 렌더하지 않는다 (안내 문구 없음) |
| 질의 실패 | 해당 턴의 단계 카드를 에러 문구로 교체, 재시도 칩 노출 |
| 조건 때문에 0곳 | 실패가 아니다 — 답변·단계는 그대로 두고 레일만 비운다. 도크에는 지역 힌트가 살아 있을 때만 `지역 넓히기` 한 장이 뜬다 |
| 사진 첨부 실패 | 토스트 "사진을 불러오지 못했어요. 사진 접근 권한을 확인해 주세요." |
| 응답 대기 중 | 도크 전송·사진·`내 근처` 비활성, 중복 질의 무시 |

토스트는 `TravelToast` — 탭바 위 150, 배경 `ink`, radius `lg`, 2.6초.
