# 여행 탭 화면 명세

> 여행 탭(구 플랜)의 구성 요소·수치·상태 전이 조회표. 전환 배경은
> [ADR 0009](../adr/0009-travel-tab-conversational-agent.md), 조건 시트 폐기와
> 조회 축 교체는 [ADR 0010](../adr/0010-travel-tab-drops-condition-sheet.md).
> 색·간격 정본은 `mobile/src/constants/theme.ts`.

탭은 홈 · 탐색 · **여행** · 마이 4개. 여행 탭만 이 문서의 범위다.

## 화면 구조

`src/app/(tabs)/travel.tsx` 한 화면 안에 3층이 쌓인다.

| 층 | 내용 | 비고 |
|---|---|---|
| 상단 바 | 워드마크 `PICTRIP` (점 없음) | 하단 1px `line` |
| 스크롤 | 헤드라인 → 핀 보드(필터 칩 + 2열 핀 그리드) → 대화 | 대화가 아래로 이어붙는 단일 스크롤 |
| 도크 | 칩 행 + 컴포저 | 탭바 위 1층 고정, 배경 `bg` + 상단 1px `line` |

헤드라인 블록 = eyebrow `VISUAL BOARD`(10.5/900, letterSpacing 1.3,
`accentText`) → `오늘,\n어디로 갈까요`(25/800, letterSpacing -0.8) → 서브
`사진을 모으고 질문을 더하면 닮은 국내 여행지로 이어드려요`(13/19 `sec`).
padding 24/20/6.

## 사진 핀

`PhotoStartCard` — 핀 보드의 **첫 번째 핀**(좌상단)이다. 점선 테두리로 콘텐츠
핀과 구분한다. CLIP 매칭이 앱의 유일한 기술 차별점이라 보드 맨 앞에 둔다.

| 요소 | 값 |
|---|---|
| 컨테이너 | 1.5px dashed `rgba(112,115,124,0.35)`, radius 16, 배경 `inset`, minHeight 178(글자 확대 시 콘텐츠만큼 늘어남), 중앙 정렬, 프레스 시 `fill` |
| 배지 | 36×36 원, 배경 `ink`, `plus` 아이콘 18 `onImage` |
| 제목 | `사진으로 찾기` 14/800 |
| 설명 | `닮은 곳을 찾아드려요` 11.5 `sec` 한 줄 |

폐기 고지(`서버에 저장하지 않고 비교 후 폐기해요`)는 핀에 없고 도크의 **첨부
배너**에만 있다 — 고지가 필요한 시점은 실제 첨부 후다.

탭 → `pickTravelPhoto()` → **선택 즉시 제출**한다. 전송 버튼을 다시 누르지
않는다. 컴포저에 이미 입력해 둔 텍스트가 있으면 사진과 함께 보낸다 — 비어 있을
때만 버블 문구를 `이 사진 같은 분위기의 여행지`로 채우고 서버에는 질문 없이
사진만 간다(Gemini 호출 없음).

## 핀 보드

레일 3단은 폐기 — 같은 채널 소스를 필터 칩 + 2열 핀 그리드로 전환했다.

| 필터 | 소스 | 카드 태그 | 위치 권한 |
|---|---|---|---|
| 전체 | hot+hidden+around 라운드로빈 병합 (`mergeBoardSpots`, contentId 중복 제거, cap 12) | **없음** (기준이 섞여 무의미) | 없으면 around 제외 |
| 인기 | `GET /v1/home/channels/hot` | `N위` | 불필요 |
| 숨은 곳 | `GET /v1/home/channels/hidden` | `N위` | 불필요 |
| 내 근처 | `GET /v1/home/channels/around?lat=&lng=` | `N.Nkm` | **필요** |

- `hot` · `hidden`은 `spot_concentration` 일일 크론(04:30 KST) 소스.
- 필터 칩 = h34 pill, 배경 `fill` + 12.5/800 `sec`, 활성 시 `ink` + `onImage`.
- 위치 권한이 없으면 `내 근처` 필터에서만 "위치를 켜면 근처를 찾아드려요" 안내
  행을 보드 위에 그린다. 사진 핀은 그대로 남는다.
- 보드에도 대화에도 `전체 ›`·`N곳 보기` 링크는 없다. 결과는 대화 레일이
  전부 담는다.
- 그리드: 좌우 20, 열·핀 간격 9, 셀은 좌→우 교대 배치, 높이 178/224 스태거
  (`boardPinHeight`: index % 3 == 1 → 224).

### 스팟 카드

사진 위에 캡션을 얹는 홈 `PostSlide` 문법. 값은 실측 기준이며 실기기에서
1.9장 걸침이 "더 있다" 신호로 약하면 170px(2장 딱 떨어짐)로 조정한다.

| 요소 | 값 |
|---|---|
| 크기 | 보드 100%×(178\|224), 대화 결과 레일 158×206, radius 16 |
| 이미지 | `cover`, 배경 `skeleton`, 로드 실패 시 opacity 0 |
| scrim | `linear-gradient(180deg, rgba(20,18,22,.16) 0%, transparent 32%, transparent 46%, rgba(16,14,18,.80) 100%)` + inset 1px `line` |
| 상태 태그 | 좌상단 9/9, h24, radius 999, 배경 `control` + blur 8, 11/800 `onImage` |
| 하트 | 우상단 9/9, 28×28, 배경 `control` + blur 8, 활성 시 `danger` + fill |
| 캡션 | 좌우 12 / 하단 12, 제목 14.5/800 `onImage` 1줄, 지역 11.5 `onDim` 1줄 |
| 탭 | 보드 카드 → 스팟 상세, 대화 레일 카드 → 첫 탭 앵커 선택(빨간 링, 나머지 딤) · 재탭 상세, 하트 → 저장 토글 + 토스트 (`scale(.975)` 프레스) |

이미지 URL은 백엔드가 서명한 `img.pictrip.org` 프록시 URL을 **그대로** 통과시킨다
(`cpyrhtDivCd=Type3`는 무변형 pass-through — [ADR 0005](../adr/0005-kto-image-policy.md)).

## 대화

채널 3단 아래, 상단 1px `line` + padding-top 22로 구분되는 영역. 턴이 비면
영역 자체가 없다. 각 턴은 아래 순서로 쌓인다.

| 순서 | 요소 | 사양 |
|---|---|---|
| 1 | 사용자 버블 | 우측 정렬, 배경 `ink` / `onImage`, radius 14, padding 11/14, 최대 폭 80%. 사진 첨부 시 버블 위에 104px 썸네일 |
| 2 | 조회 단계 카드 | 1px `line` 박스 radius 16 padding 16. 행마다 스피너 → 체크(`accentText`), 우측에 개수 배지 11/700 `accentText` on `accentFill` |
| 3 | 답변 문장 | 14.5/1.55, 숫자·핵심어는 `<b>` = `accentText` 800 |
| 4 | 결과 레일 | 응답 스팟 **전체**를 담는 가로 `FlatList`(가상화). 카드 첫 탭 = 앵커 선택, 재탭 = 상세 |
| 5 | 푸터 | 좌 카드 탭 안내 문구 11.5 `ter`, 우 피드백 버튼(토글 시 `fill` 배경) |

- 턴 등장 = `translateY(9px)` + opacity, 0.32s `cubic-bezier(.2,.7,.3,1)`.
- 단계 재생은 **클라이언트 애니메이션**이다. 서버가 실행한 단계를 순서대로
  받아 0.76초 간격으로 재생한다(3단계 = 약 2.3초). 응답이 이보다 빨리 와도
  최소 표시 시간을 지키고, 늦게 오면 마지막 단계를 스피너로 붙잡는다.
- 재생 중에는 새 질의를 받지 않는다(도크 전송 비활성).
- 후속 칩은 턴 안에 그리지 않는다 — 마지막 답변의 `refinements`가 **도크
  칩으로만** 뜬다.

## 도크

| 요소 | 사양 |
|---|---|
| 칩 행 | 마지막 답변의 후속 칩, 없으면 초기 칩 (`composerChips`) |
| 칩 공통 | h34, padding 0/16, radius 999, 1px `line`, 13.5/700 `sec`, gap 8, 가로 스크롤 |
| 컴포저 | 배경 `inset` + 1px `line`, radius 999, padding 5, margin 4/20/14 |
| `+` 버튼 | 36×36, `sec` — 사진 첨부 |
| 입력 | 14.5/500, placeholder `무엇이든 물어보세요` (첨부 시 `사진에 덧붙일 말 (선택)`) |
| 전송 | 36×36, 기본 `control`, 입력 또는 첨부가 있으면 `ink` |
| 첨부 배너 | 컴포저 위, `accentFill` + 1px `rgba(230,0,35,.24)`, 38px 썸네일 + "사진 1장 첨부됨 / 서버에 저장하지 않고 비교 후 폐기해요" |

첨부만 있고 텍스트가 없으면 **버블 문구만** `이 사진 같은 분위기의 여행지`로
채운다. 서버에는 질문 필드가 아예 실리지 않아 Gemini 호출이 없다.

## 칩

칩은 두 종류다(`lib/chips.ts`). 정형 조건 시트는 폐기됐다
([ADR 0010](../adr/0010-travel-tab-drops-condition-sheet.md)).

```ts
type Chip =
  | { kind: "question"; label: string; question: string }
  | { kind: "refine"; label: string; patch: RefinePatch };
```

**초기 칩** — 클라이언트 상수. 전부 실측으로 모수가 확인된 것만 둔다.

| 칩 = 질문 문자열 | 근거 모수 |
|---|---|
| `여기서 가까운 곳` *(라벨 `여기서 가까운 순`, 좌표 있을 때만 · 맨 앞)* | — |
| `지금 열리는 축제` | 오늘 진행 56건 (대표이미지 보유) |
| `사람 적은 바닷가` | mood `sea` 763곳 (rated 530) |
| `비 와도 갈 만한 실내` | VE06+VE07 1,906곳 |
| `제주에서 한적한 곳` | 제주 rated 264곳 |

지역은 시트가 아니라 **질문 문자열에 실어** 보낸다 — 서버의 `regionHints`
경로가 그대로 처리한다. `사람 적은 곳` 단독 칩은 두지 않는다. `숨은 관광지`
레일과 결과가 겹쳐서, 혼잡도 축에는 항상 다른 축을 하나 더 붙인다.

**후속 칩** — 서버 `refinements[]`(`{label, patch}`)를 **도크에서만** 그린다.
응답에 `refinements`가 없으면(백엔드가 앱보다 구버전) 초기 칩으로 되돌아간다.
파생 규칙과 우선순위는 서버 소유라 [api](api.md#post-agentask)에 있다. 탭하면
**마지막 답변 턴**의 `intent` + 그 칩의 `patch`를 보낸다 — 질문 문자열을
합성하지 않으므로 `여수 바다`에서 `사람 적은 곳만`을 눌러도 여수를 잃지
않는다. 과거 턴을 골라 정제하는 경로는 없다.

사진 턴의 후속 칩은 **같은 사진을 다시 첨부해** 재요청한다. 벡터가 필요해
intent 왕복만으로는 재실행할 수 없고, `Turn`이 이미 `photo`를 들고 있다.
업로드가 1회 더 들지만 동작이 정직하다.

## 앵커 후속 질문

대화 레일 카드를 탭하면 그 스팟이 **앵커**가 된다. 선택 상태는 화면 로컬
(`travel.tsx`의 `anchorSpot`)이고 서버 왕복이 없다.

| 요소 | 사양 |
|---|---|
| 선택 표시 | 선택 카드에 2.5px `accent` 링, 같은 레일의 나머지 카드 opacity 0.55 |
| 컨텍스트 필 | 독 상단에 장소명 + `×`(해제), `accentFill` 배경 + `accentText`, 우측에 "카드를 한 번 더 탭하면 상세" 안내 |
| 앵커 칩 | `근처 맛집`(food) · `근처 카페`(cafe) · `주변 볼거리`(nearby) · `오늘 붐벼?`(crowd) — refine 칩 대신 노출 |

- 앵커 칩 탭 = `/agent/ask`에 `anchor: {contentId, action}`만 보내는 새 턴.
  버블 문구는 `"{장소명} {칩 라벨}"`, `Turn.anchor`로 재시도까지 재현된다.
- 선택 해제 조건: `×` 탭, 다른 카드 탭(교체), **자유 입력 시작**, 사진 첨부,
  새 자유문 질의 전송. 자유 입력은 앵커를 싣지 않으므로 입력이 시작되는 즉시
  선택 UI를 내린다.
- `crowd` 응답은 `spots`가 빈 답변 전용 턴 — 레일 없이 답변 문장만 그린다.
  문구는 `spot_concentration` 일일 예측의 범위를 넘지 않는다("오늘 혼잡도
  예측은 … 수준").

## 상태

| 상황 | 처리 |
|---|---|
| 위치 권한 없음 | `내 근처` 필터에서만 안내 행, 전체 병합에서는 around 제외 |
| 채널 조회 실패 | 해당 채널 핀만 빠짐, 사진 핀·다른 필터·대화는 정상 |
| 질의 실패 | 해당 턴의 단계 카드를 에러 문구로 교체, 재시도 칩 노출 |
| 사진 첨부 실패 | 토스트 "사진을 불러오지 못했어요. 사진 접근 권한을 확인해 주세요." (진입 카드·`+` 버튼 공통) |
| 재생 중 | 도크 전송 비활성, 중복 질의 무시 (사진 진입 카드 포함) |

토스트는 `TravelToast` — 탭바 위 104, 배경 `ink`, radius `lg`, 2.6초.
