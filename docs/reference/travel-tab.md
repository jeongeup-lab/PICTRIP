# 여행 탭 화면 명세

> 여행 탭(구 플랜)의 구성 요소·수치·상태 전이 조회표. 전환 배경은
> [ADR 0009](../adr/0009-travel-tab-conversational-agent.md), 조건 시트 폐기와
> 조회 축 교체는 [ADR 0010](../adr/0010-travel-tab-drops-condition-sheet.md),
> 실제 지도·카드 탭·완화 칩 폐기는
> [ADR 0012](../adr/0012-travel-tab-live-map-and-card-tap.md), 턴별 각주 정리와
> 핀 색 분리는 [ADR 0013](../adr/0013-travel-tab-drops-per-turn-footnotes.md),
> 상시 지도 + 글래스 시트와 다크 전환은
> [ADR 0015](../adr/0015-travel-and-profile-go-dark-on-one-map.md).
> 색·간격 정본은 `mobile/src/constants/theme.ts`.

탭은 홈 · 탐색 · **여행** · 마이 4개. 여행 탭만 이 문서의 범위다.

## 화면 구조

`src/app/(tabs)/travel.tsx` 한 화면 안에 2층이 쌓인다.

| 층 | 내용 | 비고 |
|---|---|---|
| 지도 | `KakaoWebMap` 풀블리드, 다크(`dark` 기본 on) | 상시 배경. 우상단에 떠 있는 컨트롤, 좌상단에 질문 요약 카드 |
| 시트 | `components/GlassSheet` — 검색 필드 + 대화 | `peek`/`half`/`full` 3단, 드래그. 내리면 그게 전체 지도 |

전체 지도는 **별도 화면이 아니다**. 시트를 `peek` 아래로 내린 상태가 곧 전체
지도이므로 `/travel-map` 라우트도, 턴마다 그리던 미니맵도 없다
([ADR 0015](../adr/0015-travel-and-profile-go-dark-on-one-map.md)).

채널 보드는 폐기됐다 — 홈 탭 `ChannelTiles`와 중복이었다. 사진 진입은 검색 필드
안 아이콘 두 개(앨범·촬영)와 빈 상태의 퀵액션 `사진으로`다.

### 시트 칩

칩은 상태마다 다른 물건이다 ([ADR 0011](../adr/0011-travel-tab-chip-state-machine.md)).
표시 우선순위는 **앵커 > refine > 초기**이며 한 순간에 한 종류만 보인다.

| 상태 | 칩 | 종류 | Gemini |
|---|---|---|---|
| t=0 · 좌표 O | `근처 맛집` · `근처 볼거리` · `근처 카페` · `지금 축제` | anchor · intent | ❌ |
| t=0 · 좌표 X | `지금 축제` · `사람 적은 바닷가` · `비 와도 갈 만한 실내` · `제주에서 한적한 곳` | intent · question | 축제만 ❌ |
| t=1 결과 | `사람 적은 곳만`/`유명한 곳으로` · `실내만`(실내 결과가 있을 때만) · `가까운 순으로` | refine, 최대 3개 | ❌ |
| t=2 앵커 | `근처 맛집` · `근처 카페` · `주변 볼거리` · `오늘 붐벼?`(`hasCrowd`일 때만) | anchor | ❌ |

`근처 볼거리`만 앵커가 아니라 `intent{nearMe}` 다 — 앵커의 attraction 술어는
지도 탭용이라 박물관·전시관·공연장을 뺀다.

`새 대화`는 턴이 있을 때만 그린다(h32, radius 16, 1px `line`, 13/700 `sec`).
탭하면 `conversation-store`의 `clear()` + 로컬 초안·첨부·앵커를 비운다.

### 빈 상태

시트 안 대화 자리에 그린다 — 턴이 생기면 대화가 그 자리를 대신한다. 절대 배치
오버레이가 아니라 같은 스크롤 안의 콘텐츠라 히트 테스트 예외가 필요 없다.

| 요소 | 값 |
|---|---|
| 인사 줄 | 가로 배치 — `Mascot` 44px + 인사말/태그라인. 좌우 20, 위 16, gap 12 |
| 인사말 | `오늘, 어디로 갈까요` 21/800, letterSpacing -0.8 |
| 태그라인 | `사진 한 장으로 떠나는 여행` 12.5 `ter`, 인사말 아래 5 |
| 퀵액션 | `사진으로`(primary) · `내 근처`(좌표 있을 때만) · `축제` · `저장함` |
| 위치 프라이머 | 권한이 `undetermined` 일 때만 — `위치를 켜면 내 근처로 물어볼 수 있어요` + `켜기` |

인사말은 세로 2줄 26px 에서 **가로 1줄 21px** 로 줄였다. 시트 `peek` 높이 안에
인사·퀵액션·칩이 함께 들어가야 하는데 세로 인사말이 퀵액션을 접힘선 아래로
밀어냈다.

`저장함` 은 게스트에게 `saved-list` 인증 게이트를 태운다 — 바로 `/saved` 로
보내면 로그인 안내 대신 빈 목록을 보게 된다.

`Mascot`(`features/travel/components/Mascot.tsx`) = `react-native-svg` 단선
졸라맨. **앱 아이콘(`assets/icon.png`)과 같은 자세** — 한 팔을 들어 카메라를
쥔다. 아이콘과 화면이 같은 캐릭터를 쓰도록 맞춘 것이라, 한쪽을 바꾸면 다른
쪽도 바꾼다. viewBox `0 0 64 64`, `strokeWidth = (size / 60) * 2.6`,
`strokeLinecap/join: round`. 4.2초 주기 ±4px `translateY` 부유
(`useNativeDriver`, 빈 상태에서만 재생).

**자세만 가져오고 아이콘의 검은 타일은 가져오지 않는다.** 타일을 두면 흰 바탕에
헤어라인뿐인 빈 화면에서 유일하게 꽉 찬 형태가 돼 시선을 독점한다. 여행 탭은
조용한 한 표면이라 로고 배지보다 흰 바탕 위 검은 윤곽이 맞는다.

**카메라 렌즈는 획이 아니라 채운 점이다**(`fill`, r 2.2). 반지름이 획 두께와
비슷한 원을 그리면 획이 안쪽을 다 먹어 크기를 키워도 뭉개진 채로 남는다.
PNG 아이콘을 화면에 그대로 올리지 않는 이유도 같다 — 배경이 불투명하고,
크기에 비례하는 획 규칙과 테마 색을 따라오지 못한다.

### 결과 행

가로 카드 레일은 폐기했다 — 시트 안에서는 세로 목록이 같은 높이에 더 많이
들어가고, 사진 위 글자가 아니라 사진 옆 글자라 어두운 사진에서도 읽힌다.
값은 `features/travel/components/ResultRow.tsx`.

| 요소 | 값 |
|---|---|
| 행 | 좌우 18 / 상하 11, 행 사이 1px `line2` |
| 썸네일 | 48×48 radius 12, `cover`, 배경 `glass2` |
| 번호 | 24×24 radius 8. 앵커 있을 때 결과는 `info`, 기준점은 `accent` |
| 제목 | 15/700 `ink` 1줄 |
| 부제 | 12.5 `sec` — 지역 · 분류 |
| 거리 | 우측 14/700 `ink` + 단위 11 `ter`. 좌표가 없으면 그리지 않는다 |
| 탭 | 한 번 = 앵커 토글, 두 번 = 상세, 하트 → 저장 토글 + 토스트 |

거리는 **클라이언트가 잰다**(`lib/distance.ts`, 직선). 기준점이 있으면 그
좌표에서, 없으면 내 위치에서. 서버가 주는 값이 아니라 "차로 N분" 류는 쓰지
않는다.

목록 제목은 정렬을 주장하지 않는다(`추천 N곳`). 행은 서버가 준 관련도 순서를
그대로 도는데 제목만 `가까운 순`이라 적으면 거짓말이 되고, 나중에 기준점을
고르면 지난 턴 제목까지 바뀌었다.

이미지 URL은 백엔드가 서명한 `img.pictrip.org` 프록시 URL을 **그대로** 통과시킨다
(`cpyrhtDivCd=Type3`는 서버가 원본 URL을 내려준다 — `kto/display.py`의
`t1_display_url`, [ADR 0005](../adr/0005-kto-image-policy.md)).

## 대화

스크롤 영역 전체가 대화다(좌우 20, 상단 22). 각 턴은 아래 순서로 쌓인다.

| 순서 | 요소 | 사양 |
|---|---|---|
| 1 | 사용자 버블 | 우측 정렬, 배경 `accent` / `onImage`, radius 17(우하단 5), padding 10/14, 최대 폭 78%. 사진 첨부 시 버블 위에 104px 썸네일 |
| 2 | 조회 단계 | radius 12 `raise` 박스. 행마다 스피너 → 체크(`accentText`), 우측에 개수 배지 |
| 3 | 답변 문장 | 14.5/1.66, 숫자·핵심어는 `<b>` = `accentText` |
| 4 | 목록 머리 | `추천 N곳` + `tagBasis` 기준 줄 + (첫 결과 턴에만) 탭 안내. 11~11.5 `ter` |
| 5 | 결과 행 | 응답 스팟 전체를 `ResultRow` 로 세로 나열. 한 번 탭 = 앵커, 두 번 탭 = 상세 |

지도는 턴 안에 그리지 않는다 — 배경 지도가 마지막 답변의 스팟을 이미 들고
있고, 같은 WebView 를 턴마다 또 띄우면 메모리만 먹는다. 공간 요약
(`spatialSummary`)은 지도 좌상단 카드가 맡는다.

- 턴 등장 = `translateY(9px)` + opacity, 0.32s `cubic-bezier(.2,.7,.3,1)`.
- 단계는 **재생하지 않는다**. 대기 중에는 그 요청이 실제로 밟을 단계를
  스피너로 세워두고(`pendingSteps`), 응답이 오면 서버가 실행한 단계로
  즉시 교체하며 답변·결과 행을 같은 프레임에 붙인다. 인위적 지연은 없다.
- 대기 단계는 요청 모양이 정한다 — 자유문(의도 추출 있음)은
  `질문에서 조건 읽는 중` + `여행지 찾는 중`, `intent`·`anchor` 직송은
  `여행지 찾는 중` 하나. 서버가 Gemini를 타지 않는 경로를 그리지 않는다.
- 응답 대기 중에는 새 질의를 받지 않는다(전송 비활성).
- **자유문 후속 질문은 직전 턴을 싣는다.** 마지막으로 답이 온 턴의 `intent` 와
  결과 제목 8개를 `context` 로 보낸다. 앵커 칩을 탭해야만 이어지던 것이 말로도
  된다 — `거기 근처 카페는?` 이 동작한다. 첫 질문에는 싣지 않는다.
- **카드 탭 안내는 첫 결과 턴에만 뜨고, 앵커를 한 번 잡으면 사라진다.**
  `한 번 탭 = 이어서 묻기 · 두 번 탭 = 상세` 는 온보딩이지 내용이 아니다.
  턴마다 그리면 5턴 대화에서 같은 문장을 5번 읽는다. 판정은 화면 로컬
  `everAnchored` — 세션을 넘겨 저장하지 않는다.
- **기준 줄은 목록 위에 둔다.** 행의 태그를 설명하는 각주라 행보다
  아래에 있으면 이미 지나간 자리다.
- **기준 줄은 조직명을 적지 않는다.** 출처 표기는 마이 > 데이터 출처 문서가
  맡는다. 여기서는 무엇을 잰 값인지만 말한다 — `혼잡도 8/3 예측 기준`,
  `직선거리 기준`, `사진 유사도 기준`. 앵커 턴도 origin 을 적지 않는다 —
  답변 문장이 이미 말한다. 태그 종류는 응답마다
  균일하므로 카드가 아니라 응답 단위로 한 줄이다.
  **날짜는 결과가 전부 같은 날일 때만 적는다.** 집중률 동기화는 매칭된
  `content_id` 만 upsert 하고 빠진 행을 지우지 않아 한 응답에 다른 날짜가 섞일
  수 있다. 섞이면 날짜 없이 `혼잡도 예측 기준` 만 말한다.
- **빈 화면에는 CTA 를 두지 않는다.** 마스코트·인사말 아래에는 위치 프라이머
  한 줄만 남는다(권한이 `undetermined` 일 때만). `사진으로 찾기` 큰 버튼은
  컴포저의 앨범·촬영 아이콘과 같은 일을 두 번 시키는 물건이라 지웠다.
- **위치 프라이머는 `undetermined` 일 때만 뜬다.** 거절한 사용자에게 다시 묻지
  않고, 이미 허용한 사용자에게는 아예 안 보인다. 이전에는 권한을 **요청조차
  하지 않아** 신규 사용자가 `내 근처` 를 영영 못 봤다.
- **사진을 저장하지 않는다는 약속은 업로드 *전에* 한 번만 한다.** 첨부
  배너에 `사진은 저장하지 않아요` 로 있고, 비교 블록의 사후 문구는 지웠다 —
  이미 보낸 뒤의 안심은 쓸모가 없고 같은 약속의 두 번째 반복이었다. `폐기` 는
  쓰지 않는다(삭제 절차를 상상시켜 "그전엔 갖고 있다"로 읽힌다).
- **사진 턴은 원본과 1순위 매칭을 나란히 그린다.** 유사도 숫자만으로는 결과가
  이상할 때 내 사진 탓인지 모델 탓인지 알 수 없다. 무엇을 보고 닮았다 했는지는
  **적지 않는다** — CLIP 은 벡터를 주지 벡터에 이름을 주지 않으므로 속성을
  적으면 지어내는 것이 된다.
- **지도는 하나뿐이다.** 탭 배경의 `KakaoWebMap` 한 장이 마지막 답변의 스팟을
  들고, 시트 높이가 바뀌면 `fit` 의 아래 패딩만 다시 잰다. 턴마다 `KakaoWebMap`
  을 두면 WebView 와 SDK 로드가 N개가 되므로 미니맵은 없앴다.
- **지도는 한반도 밖으로 못 나간다.** Kakao 는 국내 타일만 주므로 위/아래로 밀면
  빈 회색이 화면을 채웠다. `clampCenter` 가 중심을 `KOREA_BOUNDS`
  (33.0~38.7N · 124.5~132.0E) 안으로 되돌리고 `setMaxLevel(12)` 가 축소 한계를
  잡는다.
- **축척 바는 끄고 Kakao 표기는 남긴다.** 지도 옵션 `$scale:false` 가 축척만
  없앤다(SDK 가 `$scale` 미지정을 true 로 읽는다). 저작권은
  `setCopyrightPosition(BOTTOMRIGHT, true)` 로 짧은 형태만 쓴다 — **로고·저작권
  자체는 지우지 않는다.** Kakao 지도 API 이용약관이 표기 삭제를 금지하고, 키가
  정지되면 지도 탭·여행 탭이 함께 죽는다.
- **다크 지도는 반전으로 만든다.** Kakao 에 다크 basemap 이 없다. `#map` 에
  `invert(1) hue-rotate(180deg)`(`DARK_FILTER`)를 걸고 `.pin`·`.sel`·`.me`·`#msg`
  에 같은 필터를 다시 걸어 되돌린다. **겹친 핀은 바깥에서만 되돌린다**
  (`.sel .pin{filter:none}`) — 안쪽까지 걸면 지도까지 세 번 반전돼 색이 도로
  어두워진다. 두 필터가 어긋나면 핀 색이 틀어지므로 상수 하나로 묶는다.
  어색하면 `KakaoWebMap` 의 `dark` 를 끄면 지도만 라이트로 돌아간다.
- **핀은 세 뜻을 갖는다.** 결과(`PIN_INK`) / 선택(`PIN_ACCENT`) / 기준점.
  `anchorId` 를 주면 그 핀이 큰 물방울 `accent` 가 되고 나머지 결과는
  `PIN_RESULT`(파랑)로 바뀐다 — "섬에서 12km 떨어진 육지"가 문장이 아니라
  그림으로 읽힌다. 색은 `buildKakaoMapHtml` 이 HTML 에 함께 굽는다.
  **색을 prop 으로 넘기면 안 된다** — `source.html` 이 바뀌어 WebView 와
  Kakao SDK 가 통째로 리마운트된다.
- **결과 핀은 카테고리 글리프를 단다.** 서버가 `spots[].categoryGroup` 을 주고
  (`lcls_systm*` → `derive_category`), `pinsFrom()` 이 그대로 통과시킨다. 지도
  탭 핀과 같은 글리프 집합이라 두 화면에서 핀 하나가 같은 뜻을 갖는다. 서버가
  분류를 못 하면(`null`) 흰 점 폴백이다 — 지도 탭도 같다.
- **공간 요약은 문장이 아니라 라벨이다.** `spatialSummary()` 가
  `{places, spread}` 를 준다 — `제주시 2곳 · 서귀포시 1곳 · +1` 과
  `최대 87km`(가장 먼 두 곳이 20km 이상일 때만). 지도 좌상단 카드가 질문과 함께
  이 줄을 든다. 문장형(`…으로 나뉘어요.`)은 순수 문법에만 8~10자를 써서 좁은
  바에서 절반이 잘렸다.
- 후속 칩은 턴 안에 그리지 않는다 — 마지막 답변의 `refinements` 가 **시트
  칩 행에만** 뜬다.

## 검색 필드

시트 머리에 고정된다 — 시트 안에서 필드가 위아래로 튀면 키보드가 올라올 때
레이아웃이 무너진다. 위에서부터 첨부 배너 → 필드 → 칩 행.

| 요소 | 사양 |
|---|---|
| 필드 | h46 radius 13, 배경 `raiseStrong` + 1px `line`, 좌우 마진 14. 앵커가 있으면 테두리 `accent` |
| 앵커 토큰 | 필드 **안** 좌측 칩 — 12/700 `accentText` on `accentFill`, 우측 `close`. 최대 폭 52% |
| 입력 | 15/600 한 줄. placeholder 는 `어디로 갈지 말해보세요` / 첨부 시 `지역이나 조건을 덧붙여 보세요` / 앵커 시 `에 대해 물어보기` |
| 촬영·앨범 | 30×32 무배경, `camera`·`image` 17 `sec` |
| 전송 | 32×32 radius 8, 기본 `fillStrong`, 입력 또는 첨부가 있으면 `accent` |
| 칩 행 | 필드 아래. 마지막 답변의 후속 칩, 없으면 초기 칩 (`composerChips`). 앵커 칩은 채운 `accent` |
| 첨부 배너 | 필드 위, `accentFill` + 1px `rgba(255,59,83,.32)`, 46px 썸네일 + "이 사진 같은 분위기로 찾아요 / 사진은 저장하지 않아요" |

앵커를 별도 배너 줄이 아니라 **필드 안 토큰**으로 넣는다. "이 문맥으로 묻는다"가
입력 지점에서 읽히고, 지우는 법도 자명하다. 세로 공간도 한 줄 아낀다.

입력에 포커스가 가면 시트가 `half` 로 올라간다.

**placeholder 는 예시를 주지 않는다.** `예: 부산에서 야경 좋은 곳` 은 예시
문장을 그대로 베껴 보내게 만들었고, 커서 옆 한 줄이 감당하기에 길었다. 지금은
서버가 요구하는 것만 말한다 — 조건이 하나도 없으면 검색 자체를 하지 않으므로
(`api.md`) placeholder 도 "조건을 달라"고 한다.
사진 강조는 카피가 아니라 **아이콘 틴트**로만 한다 — 틴트는 면적을 늘리지
않으면서 회색 일색인 컴포저에서 유일한 색이 된다. `colors.accent`가 저장(하트)·
앵커 링과 의미가 겹치는 것은 "이 앱의 주요 행동"으로 묶어 감수한다.

앨범 버튼 = `pickTravelPhoto()`, 촬영 버튼 = `shootTravelPhoto()`. 둘 다
**첨부만** 한다(전송은 별도). 액션시트가 아니라 버튼 두 개인 이유는
`ActionSheetIOS`가 iOS 전용이고 `Alert`로 대체하면 탭이 두 번이 되기 때문이다.

실패 토스트는 권한 종류가 달라 분리한다 — 앨범은 `사진을 불러오지 못했어요…`,
촬영은 `카메라를 열지 못했어요…`. 촬영은 `requestCameraPermissionsAsync()`가
거부되면 카메라를 열지 않고 토스트 경로로 보낸다.

**첨부 배너는 상태가 아니라 결과를 예고한다.** 썸네일이 이미 "첨부됨"을
말하므로 첫 줄은 그냥 보냈을 때 무슨 일이 나는지를 적는다 —
`이 사진 같은 분위기로 찾아요`. 바꿀 수 있다는 사실은 커서 옆 placeholder 가
맡는다. 첨부만 있고 텍스트가 없으면 **버블 문구만** `이 사진 같은 분위기의
여행지`로 채운다. 서버에는 질문 필드가 아예 실리지 않아 Gemini 호출이 없다.

## 칩

칩은 두 종류다(`lib/chips.ts`). 정형 조건 시트는 폐기됐다
([ADR 0010](../adr/0010-travel-tab-drops-condition-sheet.md)).

```ts
type Chip =
  | { kind: "question"; label: string; question: string }
  | { kind: "refine"; label: string; patch: RefinePatch };
```

**초기 칩** — 클라이언트 상수. 전부 실측으로 모수가 확인된 것만 둔다.

| 칩 = 질문 문자열 | 근거 모수 |
|---|---|
| `지금 열리는 축제` | 오늘 진행 56건 (대표이미지 보유) |
| `사람 적은 바닷가` | mood `sea` 763곳 (rated 530) |
| `비 와도 갈 만한 실내` | VE06+VE07 1,906곳 |
| `제주에서 한적한 곳` | 제주 rated 264곳 |

거리 질의(`여기서 가까운 곳`)는 칩 행이 아니라 빈 상태 퀵액션의 `내 근처`
다(`NEARBY_CHIP`) — 후속 칩·앵커 칩이 칩 행을 차지해도 항상 닿는다.

지역은 시트가 아니라 **질문 문자열에 실어** 보낸다 — 서버의 `regionHints`
경로가 그대로 처리한다. `사람 적은 곳` 단독 칩은 두지 않는다. `숨은 관광지`
칩과 결과가 겹쳐서, 혼잡도 축에는 항상 다른 축을 하나 더 붙인다.

**후속 칩** — 서버 `refinements[]`(`{label, patch}`)를 **시트 칩 행에서만** 그린다.
빈 배열의 뜻은 `totalCount`가 가른다: 결과가 있는 턴에서 비면 초기 칩으로
되돌아가고(백엔드가 앱보다 구버전인 경우 포함), **0곳 턴에서 비면 칩을 아예
안 낸다** — 되짚을 조건이 있는데 넓힐 지역이 없는 상태라, 여기서 `지금 축제`
같은 초기 칩을 내면 방금 실패한 조건과 무관한 제안이 답변 밑에 붙는다.
**예외는 조건이 하나도 없는 턴이다** — 응답 `intent`의 모든 축이 비어 있으면
되짚을 조건 자체가 없으므로 초기 칩으로 되돌아간다(`askedForNothing`).
`intent`를 안 주는 구버전 응답은 보수적으로 빈 채로 둔다.
파생 규칙과 우선순위는 서버 소유라 [api](api.md#post-agentask)에 있다. 탭하면
**마지막 답변 턴**의 `intent` + 그 칩의 `patch`를 보낸다 — 질문 문자열을
합성하지 않으므로 `여수 바다`에서 `사람 적은 곳만`을 눌러도 여수를 잃지
않는다. 과거 턴을 골라 정제하는 경로는 없다.

사진 턴의 후속 칩은 **같은 사진을 다시 첨부해** 재요청한다. 벡터가 필요해
intent 왕복만으로는 재실행할 수 없고, `Turn`이 이미 `photo`를 들고 있다.
업로드가 1회 더 들지만 동작이 정직하다.

## 앵커 후속 질문

대화 결과 행을 탭하면 그 스팟이 **앵커**가 된다. 선택 상태는 화면 로컬
(`travel.tsx`의 `anchorSpot`)이고 서버 왕복이 없다.

| 요소 | 사양 |
|---|---|
| 선택 표시 | 선택 행이 `accent` 톤, 같은 목록의 나머지 행 opacity 0.55, 배경 지도의 해당 핀이 라벨 달린 큰 `accent` 물방울(나머지 결과는 파랑) |
| 컨텍스트 필 | 독 상단에 장소명 + `×`(해제), `accentFill` 배경 + `accentText`, 우측에 "이 장소 기준으로 물어봐요" 안내 |
| 앵커 칩 | `근처 맛집`(food) · `근처 카페`(cafe) · `주변 볼거리`(nearby) · `오늘 붐벼?`(crowd) — refine 칩 대신 노출 |

- 앵커 칩 탭 = `/agent/ask`에 `anchor: {contentId, action}`만 보내는 새 턴.
  버블 문구는 `"{장소명} {칩 라벨}"`, `Turn.anchor`로 재시도까지 재현된다.
- **앵커는 카드 한 번 탭, 상세는 두 번 탭이다.** 전용 `여기 기준으로` 버튼은
  지웠다 — 행마다 34px 줄이 붙어 목록이 무거웠고, 이어 묻기가 상세보다 훨씬
  잦은 동작인데 더 작은 표적이었다. 판정은 `useCardTap`(260ms) 이 한다: 260ms
  안에 같은 카드가 다시 눌리면 상세, 아니면 앵커 토글. 첫 탭의 `onPressIn` 이
  이미 상세를 프리페치해 두 번째 탭이 늦게 열리지 않는다.
- **스크린 리더에서는 상세가 커스텀 액션이다.** VoiceOver·TalkBack은 사용자의
  두 번 탭을 활성화 한 번으로 바꿔 보내 `onPress`가 한 번만 오고, 그러면 항상
  앵커 토글만 걸린다. 결과 행에 `상세 보기` 접근성 액션(`ResultRow`의
  `accessibilityActions`)을 달아 로터/액션 메뉴로 상세에 닿게 한다.
- **고른 카드는 `여기 근처 ~` 의 기준점이기도 하다.** 카드를 잡고 `여기 근처
  카페` 라고 치면 그 카드 3km 반경을 돈다 — 앵커 칩을 누르지 않아도 된다.
  주변에 아무것도 없으면 에러가 아니라 `3km 안에는 … 없어요` 로 답한다.
- **자유 입력은 앵커를 유지한다.** 카드를 고르고 `여기 몇시까지 해?` 를 치면
  그 선택이 `context.focusContentId` 로 함께 간다 — 서버의 `detail` 턴이 1순위로
  쓰는 값이다([ADR 0014](../adr/0014-travel-tab-answers-not-only-searches.md)).
  0012 의 "자유 입력 시작 = 선택 해제" 규칙을 뒤집었다. 그 규칙은 앵커가 칩
  전용이던 때의 것이고, 지금은 말이 앵커를 쓰는 주된 방법이다.
- 선택 해제 조건: 같은 카드 한 번 탭, `×` 탭, 다른 카드 앵커(교체), 사진 첨부,
  `새 대화`.
- `crowd` 응답은 `spots`가 빈 답변 전용 턴 — 결과 행 없이 답변 문장만 그린다.
  문구는 `spot_concentration` 일일 예측의 범위를 넘지 않는다("오늘 혼잡도
  예측은 … 수준").

## 상태

| 상황 | 처리 |
|---|---|
| 위치 권한 없음 | `내 근처` pill을 렌더하지 않는다 (안내 문구 없음) |
| 질의 실패 | 해당 턴의 단계 카드를 에러 문구로 교체, 재시도 칩 노출 |
| 조건 때문에 0곳 | 실패가 아니다 — 답변·단계는 그대로 두고 결과 행만 비운다. 칩 행에는 지역 힌트가 살아 있을 때만 `지역 넓히기` 한 장이 뜬다 |
| 조건이 하나도 없는 질문 | 검색하지 않는다. `어디로 갈지 한 줄만 알려주세요…` 한 줄 + 초기 칩. `안녕`이 전국 20곳을 던지던 자리다 |
| 사진 첨부 실패 | 토스트 "사진을 불러오지 못했어요. 사진 접근 권한을 확인해 주세요." |
| 응답 대기 중 | 전송·사진 비활성, 중복 질의 무시 |

토스트는 `TravelToast` — 탭바 위 150, 배경 `ink`, radius `lg`, 2.6초.
