## 1. 목표

- 홈을 인스타그램 홈 피드 구조로 전면 개편: 상단 채널 타일 + 세로 게시물 피드.

  해외여행 수요를 국내로 전환하는 KTO 정책 내러티브와 정렬.
- **운영 수작업 제로**: 모든 콘텐츠가 자동 생성·자동 갱신. 어드민 역할은
  이상 게시물 숨기기(negative moderation) 하나로 축소.

## 4. 홈 — 상단 채널 타일

### 4.1 타일 줄 (포토 카드, B안)

- 세로 라운드 카드 6개 (86×110pt, radius 14), 가로 스크롤. 마지막 타일이 화면
  가장자리에 잘려 스크롤 힌트.
- 타일 = 채널 대표사진 풀블리드 + 하단 스크림 + 영어 라벨(하단 중앙, 11.5/800).
  Around만 사진 대신 연그린 배경 + 위치 핀 아이콘(현위치 성격 표시).
- 라벨(영어): `Around · Hot · Hidden · Festa · Pets · Snap`.
- 새 콘텐츠 있는 채널 = 우상단 그린 점 뱃지. 본 채널 = 타일 흐림(55%) + 뱃지 제거.
  본 상태는 로컬 저장, 매일 리셋.

### 4.2 채널 정의

| 타일 | 콘텐츠 | 데이터 소스 | 갱신 | 카드 고유 요소 | 정렬 |
|---|---|---|---|---|---|
| Around | 내 주변 여행지 | 기존 `/map/nearby` (GPS) | 실시간 | 거리 한 줄 "지금 위치에서 1.2km" | 가까운 순 |
| Hot | 지금 뜨는 관광지 TOP | KTO 집중률 `TatsCnctrRateService` → `spot_concentration` | 일일 크론 | 순위 뱃지(글래스 원형 숫자)만 — 카피 없음 | 집중률 상위 |
| Hidden | 한적한 여행지 | 동일 테이블 역정렬 + 품질 바닥 필터(대표사진·overview 필수) | 일일 크론 | 없음 (이름·지역만) | 집중률 하위 |
| Festa | 이번 주 축제 | KTO `searchFestival2` (진행 중/임박) | 일일 크론 | D-day 뱃지(액센트) + 기간·장소 한 줄 | 종료 임박순 |
| Pets | 반려동물 동반 | KTO `KorPetTourService` | 일일 크론 | 글래스 태그 "반려동물 동반 가능" | 셔플 |
| Snap | 관광공사 감성 사진 | KTO 사진갤러리 `PhotoGalleryService` | 일일 크론 | 사진 제목 + 촬영지 텍스트 | 랜덤 |

- 채널당 스팟 10개 = 카드 10장.
- **Festa·Pets·Snap은 처음 붙이는 KTO API** — 구현 전 응답 필드·쿼터·이미지
  URL 유효성 검증 태스크 선행(§10).

### 4.3 스토리 뷰어

- 타일 탭 → 풀스크린 모달. 채널 리스트는 탭 시 fetch(TanStack Query 캐시),
  로딩은 사진 스켈레톤.
- 카드 공통: 사진 풀블리드 + 이름·지역 + 채널 고유 요소(§4.2) + `저장`/`자세히 보기`.
- 상단: 진행바(카드 수만큼) + 채널 타이틀(**영어 라벨만**, 예: "Hot") + 닫기.
- 조작: 오른쪽 탭 = 다음 카드, 왼쪽 탭 = 이전, 마지막 카드에서 탭 = 다음 채널로
  이어짐(마지막 채널이면 닫기), 좌우 스와이프 = 채널 이동, 아래 스와이프 = 닫기.
- 자동 진행(5초)은 2순위 — 첫 구현은 탭 진행만.
- `자세히 보기` → 뷰어 닫고 관광지 상세 push.

### 4.4 채널별 예외

- **Around**: 권한 미허용 시 안내 카드 1장("위치를 켜면 주변 여행지를
  보여드려요" + 권한 요청 버튼). 기존 지도 탭 권한 패턴 재사용.
- **Festa**: 진행 중 축제 0건인 날은 타일 자체 숨김.
- **Snap**: 갤러리 사진은 `spots` 미매핑 독립 사진 → `저장`/`자세히 보기` 없음,
  감상 전용. 촬영지 텍스트만 표기.

## 5. 홈 — 게시물 피드 (해외→국내)

### 5.1 게시물 캐러셀 (4장, 카드 인셋 + 뉴뉴 포맷)

- 게시물 = **인셋 카드** (좌우 16px 여백, radius 16, 그림자). 카드 안이 가로
  스와이프 캐러셀 4장. 카드 아래 중앙 페이지 인디케이터(● ○ ○ ○). 좋아요·댓글·
  팔로우 없음. 다음 게시물 카드 상단이 살짝 보여 무한 스크롤 암시.
- **공통 카드 요소**: 우상단 카운터 pill `n/4` (다크 글래스).
- **1장째 (해외 훅)**: 해외 사진 풀블리드 + 하단에 이름(24/800) `|` 나라 칩 +
  **Wikidata 한국어 설명** 한 줄. **좌상단 ⓘ(사진 출처, §5.4)**. 스와이프 힌트
  UI는 없음. 피드 리스트 응답 데이터만 사용(스크롤 경량).
- **스와이프 순간**: 매칭 API 호출 → **2~4장째 국내 스팟 3곳**, 한 장에 하나.
  카드 = KTO 대표사진 풀블리드 + **번호(위첨자) + 이름 `|` 지역 칩** +
  **`overview` 첫 문장**(verbatim, 표시 절삭 최대 2줄) + **좌상단 저장(북마크)**.
  원형 보조컷(detailImage2)은 검토 후 제거 결정 — 넣지 않는다.
  카드 탭 → 관광지 상세. 로딩은 스켈레톤(캐시 히트 시 즉시).
- **LLM 카피 없음** — 소개문은 위 실데이터가 전부다. Haiku 등 생성 텍스트를
  이 화면에 넣지 않는다.

### 5.2 실시간 매칭

- 해외 스팟의 CLIP 임베딩은 ETL 때 사전 계산·저장. 스와이프 시 요청은
  `저장된 벡터 → pgvector halfvec 검색` 1회 (hnsw, 수 ms).
- 품질 게이트(실시간 실행 가능한 것만): 유사도 임계값 + 카테고리 정합 필터 +
  대표사진 존재. 임계값 수치는 구현 단계에서 실데이터로 튜닝(§10 태스크).
- 결과 3곳 미만이면 있는 만큼만 노출(0곳이면 "비슷한 국내 여행지를 찾는 중이에요"
  카드 1장). UI 프레이밍은 단정이 아닌 추천("비슷한 국내 여행지")으로 오매칭 완충.
- **Redis 캐시**: `match:{revision}:{overseasId}`, TTL 6h. 임베딩 배치와 관리자 노출
  변경은 `matching:revision`을 증가시킨다. 캐시된 국내 스팟의
  현재 이미지·노출 상태는 조회마다 검증하며, 신규·재활성 후보는 TTL 뒤 반영한다.
- 국내 카드의 `overview`·추가 이미지는 매칭 계산 시 `spot_details` 캐시에서 조인,
  미캐시 스팟은 소개문 없이 응답하고 백그라운드로 채움(기존 프리워머
  `warm_spot_details` 패턴으로 인기 스팟 사전 워밍).

### 5.3 피드 리스트

- 커서 페이지네이션 무한 스크롤. 정렬 = 유명도 기반 + 나라·카테고리 다양성 셔플
  (동일 나라 연속 노출 방지). 당겨서 새로고침 = 새 셔플.
- 숨김 처리된 게시물(§8 어드민)은 제외.

### 5.4 해외 사진 출처 시트

- 1장째 좌상단 ⓘ 탭 → 바텀 시트 3행: **촬영**(저작자명) · **라이선스**(명칭,
  탭 → 라이선스 전문 링크) · **제공**(Wikimedia Commons, 탭 → 원본 파일 페이지
  링크). 설명 문구 없음. CC 표기 의무(저작자·라이선스 링크·출처 링크)는 이
  3행+링크로 충족한다.

## 6. 탐색 페이지

- **크롬 제로**: 헤더 없음. 그리드가 상태바 아래까지 풀블리드(B안) —
  상태바 높이만큼 상단 그라데이션 스크림으로 시계 가독성 확보. 스크롤 최상단
  정지 상태에서는 첫 줄이 safe-area 아래에서 시작.
- 3열 정사각 타일(간격 1~2pt) + 6~9타일마다 2×2 큰 타일 1개(유명도 높은 스팟 우선).
- **시드 랜덤**: 진입 시 세션 시드 발급 → 그 시드로 셔플된 커서 페이지네이션
  (스크롤 중 중복 없음). 당겨서 새로고침 = 새 시드.
- 타일에 텍스트 없음. 탭 → 게시물 캐러셀 풀스크린(홈 피드 컴포넌트 재사용, §5.1).
- 데이터 = 홈 피드와 동일한 해외 스팟 풀.

## 7. 데이터 & 파이프라인

### 7.1 `overseas_spots` (신규 테이블, 백엔드 Alembic 소유)

- 컬럼(초안): `id`, `wikidata_id`(unique), `name_ko`, `name_en`, `country_code`,
  `country_name_ko`, `description_ko`, `image_url`, `image_author`,
  `image_license`, `image_license_url`, `image_source_url`, `fame_score`,
  `category`, `lat`, `lng`, `embedding halfvec(512)`, `is_hidden`,
  `created_at`, `updated_at`.
- 이미지는 **URL만 저장**(KTO 이미지 규칙과 동일 원칙). Commons 이미지는
  자유 라이선스지만 **저작자·라이선스 표기 의무** — 저작자명·라이선스명에 더해
  **라이선스 전문 URL과 원본 파일 페이지 URL**을 저장하고, 출처 시트(§5.4)의
  링크로 노출한다.

### 7.2 해외 스팟 ETL (`pipeline/` 신규 커맨드)

- Wikidata SPARQL: 관광 명소 엔티티 수집 (한국어 라벨 존재 + Commons 대표
  이미지 존재 조건). 유명도 = sitelink 수 기반 점수. 목표 규모 2,000~5,000개.
- CLIP 이미지 임베딩 배치 계산 → `embedding` 저장.
- 갱신 주기: 월 1회 수준(유명 관광지 명부는 저변동 데이터). 실행은 크론.
- 기존 KTO ETL(`pictrip-data`)과 같은 프로젝트에 서브커맨드로 추가하되,
  `overseas_spots` 테이블 소유권은 **백엔드 Alembic**(§7.1) — `sync_runs`와 달리
  백엔드가 읽고 서빙하는 핵심 테이블이므로 스키마는 백엔드가 관리, 파이프라인은
  행 적재만.

### 7.3 타일 채널 동기화 (크론, 전부 무인)

- 집중률: 기존 `scripts/sync_concentration.py` 재가동, 일일.
- 축제: `searchFestival2` 진행 중/임박분 일일 동기화(신규 테이블 or Redis 캐시 —
  구현 단계 결정, 데이터 소량이라 Redis 우선 검토).
- Pets·Snap: 응답 검증 후 동일 패턴(일일 동기화 or 요청 시 캐시) 결정.

## 8. API (신규/변경 초안)

| 엔드포인트 | 역할 |
|---|---|
| `GET /home/channels` | 채널 타일 6개 메타(라벨·썸네일·노출 여부) |

| `GET /overseas/{id}/matches` | 실시간 국내 매칭 3곳 (Redis 캐시) |

- 전부 JSend envelope + `AppError` 관례 준수.
- 어드민: 게시물(해외 스팟) `is_hidden` 토글 화면 1개 추가. 기존 큐레이션
  관리 화면은 홈에서 큐레이션이 빠지므로 단계적 정리(구현 계획에서 범위 확정).

## 10. 검증·리스크 (구현 전 확인 태스크)

1. **신규 KTO API 3종 응답 검증**: `searchFestival2` / `KorPetTourService` /
   `PhotoGalleryService` — 필드 구조, 이미지 URL 품질, 쿼터, 서비스 키 호환.
2. **Wikidata 수집 품질**: 한국어 라벨·**설명(description) 커버리지**, Commons
   이미지 화질 편차, 유명도 점수 분포. 설명 커버리지가 낮으면 한국어 위키백과
   요약 API로 보강 검토. 샘플 100개 수동 확인 1회(구축 검증이지 운영 수작업 아님).
3. **매칭 임계값 튜닝**: 유명 해외 스팟 20~30개로 매칭 결과 눈검사 →
   임계값·카테고리 필터 확정.
4. **집중률 데이터 신선도**: KTO 데이터랩 갱신 주기 재확인(작년 적재 이후 변동 여부).
5. **Commons 핫링크 정책**: 이미지 CDN(upload.wikimedia.org) 직링크 허용 조건
   및 권장 썸네일 URL 포맷 확인.
