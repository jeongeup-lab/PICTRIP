# 여행 탭 QA

> 채팅 트랜스크립트 구조의 여행 탭을 출시 전 실기기에서 확인하는 체크리스트.
> 화면 정본은 [여행 탭 화면 명세](../reference/travel-tab.md), 전환 배경은
> [ADR 0020](../adr/0020-travel-tab-chat-first-llm-writer.md).

## 목표

여행 탭의 7개 상태와 스트리밍·실패 복구를 iOS·Android에서 같은 기준으로
검증한다. **자동 테스트가 못 잡는 것만 사람이 본다** — 스트리밍 체감, 키보드,
실제 권한 다이얼로그, 지도 WebView 왕복, 실서버 SSE가 그렇다. 컴포넌트 단위
분기와 요청 payload는 Jest가 이미 잡으므로 여기서 다시 세지 않는다.

## 전제

- 최신 `dev` API에 연결한 개발 빌드와 비로그인·로그인 계정을 각각 준비한다.
- 위치 권한 `허용`·`거절` 두 상태를 재현할 수 있어야 한다.
- JPEG, HEIC와 손상 이미지, 8MB 초과 이미지를 준비한다.
- 네트워크 정상·오프라인·느린 응답을 전환할 수 있어야 한다.
- 결과가 여러 지역에 흩어지는 질문(`제주에서 한적한 곳`), 0곳으로 끝나는
  질문(`제주 실내 박물관`), 이어가는 질문(`거기 근처 맛집은?`)을 준비한다.
- 저장 결과는 마이 탭과 서버 조회로 교차 확인한다.

P0 실패는 병합·출시를 막는다. P1 실패는 담당자, 우회 방법, 수정 목표 버전을
기록해야 한다.

## 1. 7개 상태를 눈으로 확인한다

| ID | 우선순위 | 조건·동작 | 기대 결과 |
|---|---|---|---|
| TRV-001 | P0 | 여행 탭을 처음 연다 | 상단 중앙 `PICTRIP` 워드마크, 좌측 새 대화 버튼. 좌측 말풍선에 `안녕하세요, PICTRIP 어시스턴트예요.` 인사가 **타이핑**된다. 칩·패널·지도 없음 |
| TRV-002 | P0 | 질문을 보낸다 | 우측 유저 버블 → 스텝 행이 스피너→체크로 진행되고 badge(건수)가 붙는다 → 본문이 **토큰 단위로 자라며** 자동 스크롤이 따라간다 |
| TRV-003 | P0 | 결과가 여러 곳인 답을 받는다 | 본문(굵게·불릿) → 카드 캐러셀 → **지도 카드(최신 턴만)** → `소스 N` 필 → 팔로업 칩 순. 마커(`[[cards]]` 등)가 화면에 노출되지 않는다 |
| TRV-004 | P0 | 사진을 첨부해 보낸다 | 유저 버블에 첨부 썸네일. 첨부 배너에 `사진은 저장하지 않아요`가 떠 있었고, 결과 카드 성질 칩이 `유사도 N%` |
| TRV-005 | P0 | 0곳으로 끝나는 질문을 보낸다 | 실패가 아니다 — 본문이 조건 변경을 제안하고 카드·지도·출처가 없다. 장소 이름을 지어내지 않는다 |
| TRV-006 | P0 | 네트워크를 끊고 질문을 보낸다 | 빨간 띠 + `답변을 못 받았어요` + 사유 + `다시 시도`. 턴이 늘어나지 않는다 |
| TRV-007 | P0 | 새 대화 버튼을 누른다 | 진행 중 스트림이 끊기고 전체가 초기화되어 웰컴 버블로 돌아간다. 이전 턴의 늦은 이벤트가 새 대화에 새지 않는다 |

## 2. 자동 테스트가 못 잡는 것 (반드시 실기기)

| ID | 우선순위 | 조건·동작 | 기대 결과 |
|---|---|---|---|
| TRV-101 | P0 | 실서버로 질문을 보내고 첫 글자까지 시간을 잰다 | 첫 delta가 **5초 안**에 도착한다(스텝 행은 그 전에 진행). 전체 답변이 한 번에 쏟아지면 SSE 버퍼링(터널·프록시)을 의심한다 |
| TRV-102 | P0 | 지도 카드의 다른 핀을 탭한다 | 상세로 가지 않고 캐러셀이 그 장까지 스크롤하며 핀 강조가 함께 바뀐다. 카드를 넘기면 반대 방향도 같다 |
| TRV-103 | P0 | 긴 답변을 받는 동안 위로 스크롤해 이전 턴을 읽는다 | 스트리밍이 계속돼도 읽는 위치가 유지되는지, 끝나면 하단으로 튀지 않는지 본다 |
| TRV-104 | P0 | 입력 필드를 탭해 키보드를 올린다 | 컴포저가 키보드 위로 올라오고 트랜스크립트 마지막 턴이 가려지지 않는다 |
| TRV-105 | P0 | 턴을 5개 이상 쌓고 스크롤을 왕복한다 | 이전 턴에 지도 WebView가 **없고**(최신 턴만), 스크롤 지연·메모리 경고가 없다 |
| TRV-106 | P0 | `소스 N` 필을 탭한다 | 바텀시트에 블로그 제목·날짜가 뜨고 행 탭이 브라우저로 나간다. KTO 행이 항상 맨 뒤에 있다 |
| TRV-107 | P0 | VoiceOver·TalkBack으로 훑는다 | 새 대화·카드·소스·다시 시도·팔로업 칩이 각각 이름을 갖고 활성화된다 |
| TRV-108 | P1 | 본문에 별점·평점 표현이 섞이는지 20턴 훑는다 | `별점`·`평점`·`N점` 류 표현이 없다(라이터 금지 규칙). 발견 시 서버 프롬프트 이슈로 기록 |
| TRV-109 | P0 | 답변 도중 앱을 백그라운드로 보냈다 돌아온다 | 스트림이 실패하면 실패 블록 + `다시 시도`로 수습된다. 빈 턴이나 영원한 스피너가 남지 않는다 |

## 3. 질의·사진·저장 회귀

| ID | 우선순위 | 조건·동작 | 기대 결과 |
|---|---|---|---|
| TRV-301 | P0 | 응답을 기다리는 동안 전송을 반복한다 | 입력이 잠겨 있고(placeholder `답변을 만드는 중…`) 두 번째 요청이 나가지 않는다 |
| TRV-302 | P0 | 실패한 턴에서 `다시 시도`를 누른다 | 같은 payload(사진 포함)를 다시 보내고 턴이 늘어나지 않는다 |
| TRV-303 | P0 | 첫 답 뒤 `거기 근처 카페는?`을 보낸다 | 직전 턴의 intent·spots가 `context`로, 최근 턴 요약이 `history`로 함께 나간다. 답이 직전 문맥을 이어받는다 |
| TRV-304 | P0 | 팔로업 칩을 누른다 | 칩 글씨가 **글자 그대로** 새 턴의 질문이 된다. 이전 턴에는 칩이 없다(최신 done 턴만) |
| TRV-305 | P0 | 카메라 권한을 거절하거나 앨범 선택을 실패시킨다 | 각각 다른 토스트가 뜨고 작성 중인 문장이 유지되며 요청은 발생하지 않는다 |
| TRV-306 | P0 | 사진만 첨부해 전송한다 | 서버 질문 필드는 비고 유저 버블 질문 줄은 `이 사진 같은 분위기의 여행지` |
| TRV-307 | P0 | 로그인·비로그인 상태에서 카드 하트를 누른다 | 서버 성공 뒤에만 상태가 확정되고 토스트가 뜬다. 비로그인은 로그인 유도 후 잘못된 하트 상태가 남지 않는다 |
| TRV-308 | P0 | 사진 요청 뒤 서버 저장소와 구조화 로그를 점검한다 | 원본 bytes, 로컬 URI, 파일명이 저장·로그에 남지 않는다 |
| TRV-309 | P1 | 20회 이상 질문과 스크롤을 반복한다 | 입력 지연, WebView 누적, 메모리 경고, 앱 종료가 없다 |

## 검증

```bash
cd mobile
npm run lint && npm run typecheck && npm run format:check && npm test
```

여행 탭만 좁혀 돌릴 때:

```bash
cd mobile
npm test -- --runInBand src/__tests__/travel-screen.test.tsx src/features/travel
```

SSE 계약이나 라이터를 건드렸다면 백엔드 경계 테스트도 실행한다.

```bash
cd backend
NO_COLOR=1 POSTGRES_DB=pictrip_test uv run pytest tests/test_agent_chat.py tests/test_agent_writer.py
```

## 출시 판정

- P0 항목은 두 OS에서 모두 통과해야 한다.
- 자동화 명령은 모두 종료 코드 0이어야 한다.
- 사진 비영속성, 마커 노출, 장소 환각(카드에 없는 장소명), 스트림 미복구,
  저장 상태 불일치는 건수와 관계없이 출시를 차단한다.
- 실제 권한 다이얼로그, 키보드, 스크린 리더, 저사양 성능은 단말에서 최종 판정한다.

## 자주 나는 문제

| 증상 | 먼저 확인할 것 |
|---|---|
| 답변이 한 번에 통째로 도착 | 프록시·터널이 SSE를 버퍼링하는지 — 응답 헤더 `X-Accel-Buffering: no`가 살아 있는지 |
| 본문에 `[[cards]]`가 보임 | 서버 `writer.parse_stream`이 마커를 소비하는지 — 클라이언트는 마커를 모른다 |
| 카드 없이 본문만 옴 | `cards` 이벤트는 spots가 비면 안 온다 — 0곳 답이면 정상 |
| 이전 대화에 새 답이 섞임 | `chat-store`의 `activeId` 가드가 늦은 이벤트를 버리는지 |
| 재시도마다 턴이 늘어남 | `retry()`가 턴을 제자리 교체하는지 — `begin()`을 다시 타면 안 된다 |
| 지도가 이전 턴에도 뜸 | `AssistantTurn`의 `latest` 분기 — 지도는 최신 턴 전용이다 |
| 영원한 스피너 | 스트림이 done/error 없이 닫히면 `UNKNOWN` 실패 처리하는 안전망이 사는지 |
| 팔로업 칩이 오래된 문맥으로 나감 | 칩은 최신 done 턴에만 렌더된다 — 이전 턴 분기를 되살리지 않았는지 |
| 성질 칩 문구가 이상함 | 클라이언트는 서버 `tag`를 그대로 쓴다 — 서버 응답을 먼저 본다 |
| 저장 토스트가 실패 뒤에도 뜸 | `toggle()` 결과를 mutation 완료 뒤 처리하는지 |
