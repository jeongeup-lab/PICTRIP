# 여행 탭 QA

> 현재 여행 탭의 시작 화면부터 질문, 사진, 장소 카드, 지도, 저장까지 출시 전 확인하는 체크리스트.

## 목표

여행 탭의 핵심 경로와 실패 복구를 iOS·Android에서 같은 기준으로 검증한다. 이
문서는 현재 대화형 여행 탭만 다룬다. 폐기된 채널 보드와 사진 시작 CTA는 범위에
포함하지 않는다.

## 전제

- 최신 `dev` API에 연결한 개발 빌드와 비로그인·로그인 계정을 각각 준비한다.
- 위치 권한은 `미결정`, `허용`, `거절` 세 상태를 재현할 수 있어야 한다.
- JPEG, PNG, WebP, HEIC와 손상 이미지, 8MB 초과 이미지를 준비한다.
- 네트워크 정상·오프라인·느린 응답을 전환할 수 있어야 한다.
- 저장 결과는 마이 탭과 서버 조회로 교차 확인한다.

P0 실패는 병합·출시를 막는다. P1 실패는 담당자, 우회 방법, 수정 목표 버전을
기록해야 한다.

## 1. 시작 화면과 위치

| ID      | 우선순위 | 조건·동작                                                         | 기대 결과                                                                                     |
| ------- | -------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| TRV-001 | P0       | 여행 탭을 처음 연다                                               | 중앙 `PICTRIP`, 마스코트, `오늘, 어디로 갈까요`, 칩과 컴포저가 보이며 폐기된 채널 보드는 없다 |
| TRV-002 | P0       | 턴이 없는 상태에서 입력창과 칩을 누른다                           | 투명 인사 오버레이가 터치를 막지 않고 입력·칩이 동작한다                                      |
| TRV-003 | P1       | 첫 질문을 전송한다                                                | 인사 화면이 180ms로 사라지고 접근성 탐색에서도 제외된다                                       |
| TRV-004 | P0       | 대화가 생긴 뒤 `새 대화`를 누른다                                 | 턴, 초안, 사진 첨부, 선택 장소가 모두 비워지고 시작 상태로 돌아온다                           |
| TRV-005 | P0       | 위치 권한이 미결정인 새 설치에서 위치 시작 액션을 누르고 허용한다 | 권한 요청 후 좌표를 얻고 `내 근처`와 위치 기반 초기 칩을 사용할 수 있다                       |
| TRV-006 | P0       | 위치 권한 요청을 거절한다                                         | 앱이 종료되지 않고 위치 시작 액션과 `내 근처`가 사라지며 일반 질문은 가능하다                 |
| TRV-007 | P1       | 이미 허용하거나 거절한 상태로 다시 연다                           | 권한을 반복 요청하지 않고 미결정일 때만 위치 시작 액션이 보인다                               |
| TRV-008 | P0       | 위치 조회 API가 실패하거나 좌표를 반환하지 않는다                 | 여행 탭이 정상 렌더되고 위치 기능만 비활성화된다                                              |

## 2. 질문과 대화

| ID      | 우선순위 | 조건·동작                                                    | 기대 결과                                                                   |
| ------- | -------- | ------------------------------------------------------------ | --------------------------------------------------------------------------- |
| TRV-101 | P0       | 텍스트 질문을 전송한다                                       | 사용자 버블과 대기 단계가 한 번 생기고 중복 요청이 없다                     |
| TRV-102 | P0       | 응답을 기다리는 동안 전송을 반복한다                         | 컴포저가 비활성화되어 동시에 두 턴이 시작되지 않는다                        |
| TRV-103 | P0       | 정상 응답을 받는다                                           | 서버 단계, 답변, 전체 결과 카드가 같은 턴에 표시되고 입력이 다시 활성화된다 |
| TRV-104 | P0       | 결과가 0곳인 정상 응답을 받는다                              | 실패로 오인하지 않고 안내 답변을 표시하며 무관한 초기 칩을 붙이지 않는다    |
| TRV-105 | P0       | 네트워크 오류 후 `다시 시도`를 누른다                        | 기존 실패 턴에서 같은 payload를 다시 보내며 턴이 늘어나지 않는다            |
| TRV-106 | P0       | 첫 답변 뒤 `거기 근처 카페는?`를 입력한다                    | 직전 완료 답변의 의도와 장소 문맥을 포함해 후속 질문한다                    |
| TRV-107 | P0       | 첫 질문을 보낸다                                             | 이전 대화 문맥이 요청에 포함되지 않는다                                     |
| TRV-108 | P0       | 후속 조건 칩을 누른다                                        | 최신 완료 턴의 `intent + patch`를 보내고 칩 라벨이 새 버블에 보인다         |
| TRV-109 | P1       | 구형 응답처럼 `refinements`가 없도록 재현한다                | 화면이 깨지지 않고 결과 유무에 맞는 안전한 칩 상태로 돌아간다               |
| TRV-110 | P0       | 국내 여행 범위를 벗어난 질문, 요청 제한 오류를 각각 재현한다 | 임의 추천 없이 원인에 맞는 안내와 재시도 경로가 보인다                      |

## 3. 앨범과 카메라

| ID      | 우선순위 | 조건·동작                                                  | 기대 결과                                                                        |
| ------- | -------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------- |
| TRV-201 | P0       | 앨범 버튼에서 사진을 선택한다                              | 요청은 아직 발생하지 않고 `이 사진 같은 분위기로 찾아요 / 사진은 저장하지 않아요` 배너와 썸네일이 보이며, placeholder가 `지역이나 조건을 덧붙여 보세요`로 바뀐다 |
| TRV-202 | P0       | 카메라 권한을 허용하고 촬영한다                            | 촬영 사진이 앨범과 같은 첨부 경로에 들어가며 자동 전송되지 않는다                |
| TRV-203 | P0       | 사진만 첨부해 전송한다                                     | 서버 질문 필드는 비고 버블은 `이 사진 같은 분위기의 여행지`로 표시된다           |
| TRV-204 | P0       | 문장을 입력하고 사진을 첨부해 전송한다                     | 문장과 사진이 하나의 요청으로 정확히 한 번 전송된다                              |
| TRV-205 | P0       | 첨부 배너의 닫기를 누른다                                  | 사진만 제거되고 작성 중인 문장은 유지된다                                        |
| TRV-206 | P0       | 앨범 선택기가 실패한다                                     | 앨범 오류 토스트가 보이고 초안이 유지되며 요청은 발생하지 않는다                 |
| TRV-207 | P0       | 카메라 권한을 거절하거나 카메라 실행을 실패시킨다          | 카메라 오류 토스트가 보이고 초안과 앨범 버튼은 그대로 유지된다                   |
| TRV-208 | P1       | 앨범 선택 또는 촬영을 취소한다                             | 오류나 빈 턴 없이 컴포저로 돌아온다                                              |
| TRV-209 | P0       | JPEG, PNG, WebP, HEIC와 명시적 미지원 MIME을 각각 사용한다 | 지원 형식은 원 MIME으로 전송되고 미지원 형식은 안전한 오류로 끝난다              |
| TRV-210 | P0       | 사진 결과의 후속 칩과 실패 턴 재시도를 실행한다            | 같은 로컬 사진, `intent`, `patch`를 다시 사용하고 실패 턴을 중복 생성하지 않는다 |

## 4. 장소 카드, 지도, 저장

| ID      | 우선순위 | 조건·동작                                                  | 기대 결과                                                                     |
| ------- | -------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------- |
| TRV-301 | P0       | 결과 카드를 한 번 누르고 260ms 기다린다                    | 상세로 가지 않고 선택 링, 나머지 카드 딤, 장소 기준 칩이 표시된다             |
| TRV-302 | P0       | 같은 결과 행을 260ms 안에 두 번 누른다                     | 해당 장소 상세 화면으로 한 번 이동한다                                        |
| TRV-303 | P0       | 선택한 행을 다시 한 번 누른다                              | 장소 선택과 딤이 해제되고 최신 후속 조건 칩으로 돌아간다                      |
| TRV-303a| P1       | 첫 결과 턴에서 행을 앵커로 잡은 뒤 다음 질문을 보낸다      | 탭 안내는 첫 결과 턴에만 있었고, 앵커를 한 번 잡은 뒤로는 어느 턴에도 없다    |
| TRV-304 | P0       | 장소 선택 후 자유 입력을 시작하거나 사진을 첨부한다        | 앵커가 즉시 해제되고 이후 요청에 이전 `contentId`가 포함되지 않는다           |
| TRV-305 | P0       | 장소 기준 `근처 맛집`, `근처 카페`, `주변 볼거리`를 누른다 | 선택한 `contentId + action`만 보내고 결과를 새 턴에 표시한다                  |
| TRV-306 | P0       | 장소 기준 질문을 실패시킨 뒤 재시도한다                    | 원래 `contentId + action`으로 같은 턴을 재사용한다                            |
| TRV-307 | P0       | 좌표가 있는 결과를 받는다                                  | 배경 지도가 결과에 맞춰지고 모든 결과 핀이 **잉크색**으로 보인다              |
| TRV-307a| P0       | 결과 행을 한 번 눌러 앵커를 잡는다                         | 그 핀만 라벨 달린 **빨간** 물방울이 되고 나머지 결과 핀은 **파랑**으로 바뀐다 |
| TRV-308 | P1       | 전국에 멀리 떨어진 결과를 받는다                           | 지도 뷰가 전체 핀을 담고 좌상단 카드에 분포 요약이 보인다                     |
| TRV-309 | P0       | 시트를 아래로 끌어내렸다가 다시 올린다                     | 시트가 peek·half·full 로 스냅하고 지도·대화 상태가 그대로 유지된다            |
| TRV-309a| P1       | 다크 지도에서 기준점 핀과 결과 핀 색을 본다                | 기준점은 빨강, 결과는 파랑이며 반전 필터로 색이 뒤집히지 않는다               |
| TRV-310 | P0       | 로그인 상태에서 하트를 눌러 저장·해제한다                  | 서버 성공 뒤에만 상태가 확정되고 각각 성공 토스트가 보이며 마이 탭과 일치한다 |
| TRV-311 | P0       | 비로그인 상태에서 하트를 누른다                            | 로그인 유도 후 거절하면 저장 토스트나 잘못된 하트 상태가 남지 않는다          |
| TRV-312 | P0       | 저장·해제 API를 실패시킨다                                 | 낙관 상태가 원래 값으로 롤백되고 성공 토스트가 표시되지 않는다                |

## 출시 판정

- P0 39건은 두 OS에서 모두 통과해야 한다.
- 자동화 명령은 모두 종료 코드 0이어야 한다.
- 사진 비영속성, 잘못된 장소 추천, 중복 요청, 상세 진입 불가, 저장 상태 불일치는
  건수와 관계없이 출시를 차단한다.
- 실제 권한 다이얼로그, 키보드, 스크린 리더, 저사양 성능은 단말에서 최종 판정한다.

## 자주 나는 문제

| 증상                         | 먼저 확인할 것                                                              |
| ---------------------------- | --------------------------------------------------------------------------- |
| `내 근처`가 없음             | OS 권한 상태가 미결정인지, 좌표 획득이 성공했는지                           |
| 후속 칩이 이전 질문을 바꿈   | 가장 최근 완료 턴의 `intent`를 쓰는지, 라벨을 질문 문자열로 보내지 않았는지 |
| 카드 첫 탭에 상세가 열림     | `useCardTap`의 260ms 판정과 카드별 타이머를 확인                            |
| 저장 토스트가 실패 뒤에도 뜸 | `toggle()`의 `true/false/null` 결과를 mutation 완료 뒤 처리하는지           |
| 사진 선택과 동시에 요청됨    | 앨범·카메라 핸들러가 첨부만 하고 전송은 컴포저가 맡는지                     |
| 재시도할 때 턴이 늘어남      | 실패 턴 ID와 원래 질문·사진·intent·patch·anchor·context를 재사용하는지      |
