# S13 홈·탐색 전면 개편 — 구현 계획 개요

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement plan-by-plan, task-by-task.
> 이 문서는 4개 실행 계획의 마스터 인덱스다. 실행 순서·의존성·공유 계약(인터페이스)의
> SSOT이며, 개별 태스크는 각 계획 문서에 있다.

**Goal:** `docs/specs/S13-home-feed-explore-redesign.md`(결정 12개 락) + UI SSOT
`docs/mockups/redesign-2026-07-cc/app-prototype.html`대로 홈·탐색을 전면 개편한다.

**Architecture:** 백엔드에 신규 `feed` 모듈(overseas_spots 서빙 + 채널 집계 + 매칭),
파이프라인에 Wikidata ETL 서브커맨드, 모바일에 features/channels·feed(재작성)·explore.
기존 CLIP 임베딩 인프라(`spot_embeddings` + hnsw)는 매칭 엔진으로 재사용한다.

**Tech Stack:** FastAPI + SQLAlchemy 2.0 async + pgvector halfvec + Redis /
psycopg3 + httpx + typer (pipeline) / Expo SDK 56 + TanStack Query + zustand (mobile).

## Global Constraints (모든 태스크에 적용)

- 코드 주석 금지. 커밋/PR에 문맥을 남긴다.
- KTO·Commons 이미지는 **URL만 저장** — 다운로드/바이너리 저장 금지.
- KTO `overview`는 verbatim — 첫 문장 추출은 절삭만 허용, 문자 수정 금지.
- LLM(Haiku) 미사용 — 생성 텍스트를 어떤 화면에도 넣지 않는다.
- 모든 API 응답 = JSend `ok()`/`err()`, 오류는 `AppError` 서브클래스.
- routes.py는 services/schemas/app.core만 import (import-linter 계약 갱신 포함).
- cross-module 접근은 상대 모듈 `services` 경유. admin만 예외(자체 repositories).
- `sync_runs`는 pipeline 소유 — 백엔드 Alembic autogenerate 제외 유지.
- `overseas_spots`는 **백엔드 Alembic 소유** — pipeline은 행 적재만.
- 모바일: 이모지 금지, 신규 네이티브 모듈 금지(react-native-svg·PanResponder·RN Modal로 해결),
  `err.code`로만 분기, 파일명 규칙(컴포넌트 PascalCase, 런타임 모듈 kebab-case).
- 백엔드 테스트: `POSTGRES_DB=pictrip_test NO_COLOR=1 uv run pytest`.
- 모바일 게이트: `npm run lint && npm run typecheck && npm run format:check && npm test`.
- 어드민 UI 변경은 `admin/mockups/`와 `backend/app/modules/admin/static/` **양쪽 동일 반영**(CI drift check).
- dev 머지 = 즉시 프로덕션. 아래 롤아웃 순서를 지킨다.

## 롤아웃 안전 순서 (스테이징 없음)

1. **A·B는 전부 추가(additive)** — 기존 화면·API를 건드리지 않으므로 태스크 단위 dev 머지 안전.
2. **C는 스택형**: 신규 feature 코드·컴포넌트는 라우트 미연결로 먼저 머지(앱 외관 불변).
   `(tabs)/` 밑에 파일을 추가하는 순간 탭이 생기므로, 탭 플립(C6)은 단일 PR로:
   탭바 교체 + `(tabs)/explore.tsx`·홈 교체 + photo 라우트/피처 삭제를 원자적으로 머지.
3. **C6 머지 전 게이트**: prod에서 `/v1/feed`·`/v1/home/channels`·`/v1/overseas/{id}/matches`
   실데이터 응답을 curl로 확인. ETL 부트스트랩(A8)과 집중률 적재(B6)가 선행돼야 한다.
4. **D는 유예 후**: C6 OTA 배포 뒤 구버전 JS가 `/home/feed`·`/taste/photo-search`를
   더 이상 호출하지 않음을 오리진 로그로 확인(며칠 유예)한 다음 제거.

## 공유 계약 (계획 간 인터페이스 SSOT)

### DB: `overseas_spots` (마이그레이션 `0018_overseas_spots`, 백엔드 소유)

```
id               BigInteger Identity PK
wikidata_id      String(32)  UNIQUE NOT NULL      -- "Q1234"
name_ko          String(255) NOT NULL
name_en          String(255) NULL
country_code     String(2)   NOT NULL             -- ISO 3166-1 alpha-2
country_name_ko  String(80)  NOT NULL
description_ko   Text        NULL                 -- Wikidata ko description
image_url        Text        NOT NULL             -- Commons Special:FilePath?width=800
image_author     Text        NULL
image_license    String(80)  NULL                 -- "CC BY-SA 4.0"
image_license_url Text       NULL
image_source_url Text        NOT NULL             -- File: 페이지
fame_score       Integer     NOT NULL DEFAULT 0   -- sitelink 수
category         String(40)  NULL
lat / lng        Float       NULL
embedding        halfvec(512) NULL (raw DDL, hnsw halfvec_cosine_ops 인덱스)
is_hidden        Boolean     NOT NULL DEFAULT false
created_at / updated_at  timestamptz
인덱스: uq(wikidata_id), hnsw(embedding), idx(is_hidden, fame_score DESC)
```

### API 페이로드 계약 (JSend `data` 내부, camelCase)

```
GET /v1/feed?seed&cursor&limit=6
  → { seed: str, items: [OverseasPost], nextCursor: str|null, hasMore: bool }
OverseasPost = { id:int, nameKo, countryCode, countryNameKo, descriptionKo:str|null,
                 imageUrl, imageAuthor:str|null, imageLicense:str|null,
                 imageLicenseUrl:str|null, imageSourceUrl }

GET /v1/explore?seed&cursor&limit=30
  → { seed, items: [OverseasPost], nextCursor, hasMore }   # 피드와 동일 스키마 재사용

GET /v1/overseas/{id}/matches
  → { overseasId:int, matches: [MatchCard] }               # 0~3개
MatchCard = { contentId, title, regionLabel, imageUrl, overviewFirst:str|null }

GET /v1/home/channels
  → { channels: [ChannelMeta] }                            # festa 0건이면 목록에서 제외
ChannelMeta = { key, label, thumbnailUrl:str|null, available:bool }
  key ∈ around|hot|hidden|festa|pets|snap · label = 영어 그대로

GET /v1/home/channels/{key}?lat&lng                        # lat/lng는 around만 필수(없으면 422)
  → { key, label, cards: [ChannelCard] }                   # 최대 10장
ChannelCard = { contentId:str|null, title, regionLabel, imageUrl:str|null,
                dist:float|null, rank:int|null, dday:str|null, line:str|null,
                tag:str|null, saveable:bool }
  around: dist 채움 / hot: rank / festa: dday+line(기간·장소) / pets: tag /
  snap: contentId=null·saveable=false·line=촬영지
```

## 핵심 결정 (스펙 밖에서 이 계획이 확정하는 것)

1. **CLIP 임베딩 배치는 백엔드 스크립트** (`scripts/embed_overseas.py`). 스펙 §7.2는
   파이프라인 배치를 상정했지만 CLIP(torch·transformers)은 백엔드가 이미 소유하고
   파이프라인은 ML 의존성이 0이다. 파이프라인 = 행 적재, 백엔드 = 임베딩·서빙으로
   기존 `spot_embeddings` 분업과 동일하게 간다.
2. **백엔드 신규 모듈명 = `feed`** (8번째 모듈). 홈 채널·피드·탐색·매칭이 한 도메인.
3. **`kto_client`를 `app/core/kto_client.py`로 승격** — feed 모듈도 KTO를 호출하게 되어
   2+ 모듈 소비 조건 충족 (core 승격 규칙 그대로).
4. **festa·pets·snap은 크론 없이 요청 시 fetch + Redis 자정 TTL 캐시** (스펙 §7.3의
   "Redis 우선 검토" 채택). hot/hidden만 `sync_concentration` 일일 크론(GH Actions).
5. **어드민 쓰기 범위 확장**: `curations`/`curation_spots` + `overseas_spots.is_hidden`.
   CLAUDE.md의 admin 예외 조항을 함께 갱신한다.
6. **큐레이션 표면은 D에서 일괄 제거** (모바일 화면·`/curations/{slug}`·어드민 편집기·
   `/home/feed`). DB 테이블(`curations`·`curation_spots`)은 남기고 드롭은 후속 판단.
7. **피드 정렬 = 시드 결정적 가중 셔플** — `pow(uniform_hash(seed,id), 1/ln(fame+2))`
   내림차순 keyset 페이지네이션. 같은 시드에서 순서 고정(스크롤 중복 없음), 새로고침 = 새 시드.
   나라 연속 중복은 페이지 후처리로 완화. 탐색도 동일 쿼리 재사용.
