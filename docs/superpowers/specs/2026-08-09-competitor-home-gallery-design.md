# 경쟁작 홈 화면 갤러리 설계

## 목표

PicTrip과 콘셉트가 겹치는 핵심 경쟁작 7개의 홈 화면을 PNG로 보존하고, 한 페이지에서 시각적으로 비교할 수 있는 정적 HTML 갤러리를 만든다.

## 대상

1. TripCraft Korea
2. NextSpot
3. Gangneung Node
4. TapGyeong
5. TripPing
6. 에움길
7. IT-DA

## 화면 수집 원칙

- 라이브 배포가 있으면 현재 공개 홈 화면을 직접 캡처한다.
- 라이브가 없으면 저장소가 공개한 공식 홈 목업 또는 제출 화면을 사용한다.
- 공개 홈 UI가 전혀 없으면 임의로 경쟁작 UI를 창작하지 않고 `공개 홈 UI 없음` 상태 이미지를 만든다.
- 모든 카드에 출처 상태를 `LIVE`, `REPO MOCKUP`, `NO PUBLIC UI` 중 하나로 표시한다.
- 데스크톱 서비스는 1440×1000, 모바일 중심 서비스는 430×932 뷰포트를 우선 사용하되, HTML에서는 이미지 원본 비율을 유지한다.

## 산출물

- 위치: `ai-shared/competitor-home-gallery-2026-08-09/`
- 프로젝트별 PNG: `screenshots/`
- 비교 페이지: `index.html`
- 간단한 출처·상태 목록: `README.md`

## HTML 구성

- 상단: 기준 시각과 수집 원칙
- 본문: 7개 프로젝트 카드 그리드
- 각 카드: 프로젝트명, 출처 상태, 홈 화면 이미지, 한 줄 홈 진입 플로우, GitHub/Live 링크
- 이미지 클릭 시 원본 PNG를 새 탭에서 확인
- 필터나 복잡한 상호작용은 넣지 않는다. 홈 화면 비교가 목적이므로 정적 갤러리로 유지한다.

## 오류·예외 처리

- 배포가 200이 아니거나 렌더링이 실패하면 저장소 목업으로 내린다.
- 로그인이나 API 키 없이는 홈이 렌더링되지 않으면 해당 제한을 카드에 기록한다.
- 라이브와 저장소 목업을 혼합할 때는 캡처 날짜와 출처 상태를 명확히 표시한다.

## 검증

- 7개 카드가 모두 존재하는지 확인한다.
- 모든 로컬 이미지 참조가 실제 파일로 해석되는지 검사한다.
- 모든 GitHub 링크와 공개 Live 링크의 응답을 확인한다.
- HTML을 실제 브라우저로 렌더링하고 데스크톱·모바일 폭에서 카드와 이미지가 잘리지 않는지 시각 검수한다.
