# 0013. 여행 탭이 턴마다 자기 설명을 하지 않는다

- 상태: 채택
- 날짜: 2026-08-06
- 관련: [travel-tab](../reference/travel-tab.md), [api](../reference/api.md),
  [0009 여행 탭 대화형 에이전트](0009-travel-tab-conversational-agent.md),
  [0012 실제 지도·카드 탭](0012-travel-tab-live-map-and-card-tap.md)

## 맥락

실기기에서 결과 턴 하나가 이 순서로 쌓인다 — 답변 문장, 공간 요약 문장, 카드
소개 줄 N개, `tagBasis`, 카드 탭 안내. 사진 턴이면 첨부 배너와 비교 블록이
같은 약속("저장하지 않는다")을 두 번 더 한다. **내용과 설명서가 같은 흐름에
섞여 턴마다 반복된다.** 5턴이면 탭 안내를 5번 읽는다.

개별로도 어긋난 곳이 있다.

- **핀 색이 선택을 구분하지 못한다.** 0012가 턴 지도 핀을 전부 `accent` 로
  칠했다. 선택 핀도 같은 빨강이라 차이가 크기·라벨뿐이고, `accent` 는 이미
  하트·앵커 링·첨부 배너·태그가 함께 쓴다.
- **셰브론 하나가 두 목적지를 가리킨다.** 턴 지도의 `지도에서 보기` 와 지도
  화면 카드의 상세가 둘 다 `chevron-right` 다. 후자는 라벨 없는 16px + hitSlop
  8 = 32px 로 44pt 최소 표적에도 못 미치고, 카드 Pressable 안에 중첩이라
  경계도 없다.
- **공간 요약이 잘린다.** 문장형이라 순수 문법에만 8~10자를 쓴다. 턴 지도 바의
  요약 폭은 약 235px(≈19자)인데 실제 문자열은 40자까지 간다.
- **placeholder 가 기능 나열이다.** `사진을 올리거나 물어보세요` 는 바로 아래
  앨범·촬영 아이콘과 위쪽 인사말이 이미 하는 말을 세 번째로 한다. 자유문이
  된다는 사실은 어디서도 안 가르친다.
- **카드 소개 줄이 "왜 이 장소인가"에 답하지 않는다.** `overview` 첫 문장은
  백과사전 도입부다. 그 질문에는 태그(`4.2km`·`유사도 86%`)와 `tagBasis` 가
  이미 답한다. 40px × N 이 레일 높이를 21% 늘리고, 11px 2줄은 가로 스크롤
  중에 읽히지 않는다.

## 결정

**설명서는 한 번만 말하고, 표적은 서로 다르게 생긴다.**

- **기본 핀은 잉크, 선택 핀만 빨강이다.** 두 색을 HTML 에 함께 굽고
  `pinEl()` 의 `sel` 분기가 고른다 — 색을 prop 으로 바꾸면 `source.html` 이
  달라져 WebView 와 Kakao SDK 가 리마운트된다. 지도 탭과 핀 문법도 통일된다.
- **카드 탭 안내는 첫 결과 턴에만, 앵커를 한 번 잡으면 사라진다.** 세션 로컬
  상태(`everAnchored`)로 판정한다. 배운 사람에게 다시 가르치지 않는다.
- **`tagBasis` 는 레일 위로 올리고 줄인다.** 태그를 설명하는 각주가 190px
  아래에 있으면 이미 지나간 자리다. `현재 위치에서 직선거리` → `직선거리 기준`,
  `사진과의 CLIP 벡터 유사도` → `사진 유사도 기준`. 앵커 턴도 origin 을 빼고
  같은 문자열을 쓴다 — 답변 문장이 이미 origin 을 말한다.
- **프라이버시 문구는 업로드 전 한 번뿐이다.** 첨부 배너는 상태(`사진 1장
  첨부됨`) 대신 결과를 예고하고(`이 사진 같은 분위기로 찾아요`), 안심은 짧게
  (`사진은 저장하지 않아요`) 받친다. 비교 블록의 사후 문구는 지운다. `폐기` 는
  쓰지 않는다 — 삭제 절차를 상상시켜 오히려 "그전엔 갖고 있다"로 읽힌다.
- **공간 요약은 문장이 아니라 라벨이고, 지역과 거리로 쪼갠다.**
  `spatialSummary()` 가 `{places, spread}` 를 준다 — `제주시 2곳 · 서귀포시 1곳`
  + `최대 87km`. 좁은 자리는 지역만, 넓은 자리는 둘 다 쓴다.
- **`지도 열기` 는 `map-pin` 글리프를 쓰고, 지도 화면 상세는 `상세` 라고 적는다.**
  표면 전환과 레코드 진입은 다른 동작이니 다른 기호여야 한다. 상세는 세로
  구분선 + 전체 높이 표적으로 카드 본문과 갈라 놓는다(카드 232 → 248px).
- **placeholder 는 예시를 준다** — `예: 부산에서 야경 좋은 곳`. 칩이 쓰지 않는
  축(`night`)에 지역을 얹어 "지역+분위기를 말로 조합해도 된다"를 가르친다.
  첨부 시에는 `지역이나 조건을 덧붙여 보세요` 로 바뀐다.
- **카드 소개 줄을 지운다**(168×190 → 168×150). 서버의 `_with_blurbs` 와
  `AgentSpotCard.blurb`, `load_fresh_overview_map` 도 함께 지운다 — 아무도 안
  그리는 값을 위해 응답마다 DB 왕복을 하지 않는다.

## 고려한 대안

- **핀 색은 두고 선택 핀만 키우기** — 이미 그렇게 되어 있고(28→34px + 라벨),
  그것으로 부족하다는 것이 문제의 출발점이다. 기각.
- **사진을 고르면 바로 전송** — 두 단계가 한 단계가 되지만 "부산에서"를 덧붙일
  수 없다. 그게 사진 검색의 값어치이고, 다시 하려면 사진을 또 골라야 한다. 기각.
- **탭 안내를 영구 저장으로 숨기기** — 저장소를 하나 더 붙일 값어치가 없다.
  세션 안에서 한 번 배우면 그 세션은 조용하고, 다음 세션의 첫 턴 한 줄은
  비용이 아니다. 기각.
- **상세를 테두리 친 원형 셰브론으로** — 버튼으로 읽히긴 하지만 여전히
  "셰브론 = 상세"라는 학습에 기댄다. 지적된 문제가 정확히 그것이라 글자로
  적는다. 기각.
- **`지도에서 보기` 텍스트를 통째로 빼고 아이콘만** — 폭은 가장 많이 벌지만
  1차 내비게이션 어포던스를 아이콘 하나에 맡기게 된다. 살아 있는 지도 밑에서
  `지도에서 보기` 가 이미 어색했으므로 `지도 열기` 로 줄이는 선에서 멈춘다. 기각.
- **카드 소개 줄을 1줄로 줄이기** — 높이는 절반이 되지만 "읽히지 않는 백과사전
  도입부"라는 성질은 그대로다. 기각.

## 결과

**0012 의 "턴 지도의 핀은 빨강이다" 는 폐기된다.** 핀 색은 앱 전체에서
잉크(결과) / 빨강(선택) 한 가지 뜻만 갖는다.

**`AgentSpotCard.blurb` 가 응답에서 사라진다.** 구버전 앱은 필드가 없으면 소개
줄을 비우므로 카드가 깨지지 않는다. `overview` 원문 무변형 원칙은
[0005](0005-kto-image-policy.md) 가 계속 들고 있다 — 여행 탭이 더는 그 값을
쓰지 않을 뿐이다.

**`tagBasis` 문자열이 바뀐다.** 모바일은 서버 문자열을 그대로 그리므로 앱
업데이트가 필요 없다.
