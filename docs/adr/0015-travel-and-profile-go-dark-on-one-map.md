# 0015. 여행 탭은 지도 하나 위에서 돌고, 앱은 다크로 간다

- 상태: 채택
- 날짜: 2026-08-08
- 관련: [travel-tab](../reference/travel-tab.md),
  [0012 실제 지도·카드 탭](0012-travel-tab-live-map-and-card-tap.md),
  [0013 턴마다 자기 설명을 하지 않는다](0013-travel-tab-drops-per-turn-footnotes.md)

## 맥락

지도가 세 곳에 흩어져 있었다 — 스팟 상세에서만 닿는 `/map`, 여행 탭 전용
`/travel-map`, 대화 안에 턴마다 그리던 `TurnMap`. 같은 카카오 WebView 를 세 번
띄우고, 대화에서 지도를 보려면 라우트를 밀고 들어갔다가 뒤로 나와야 했다.

팔레트도 갈라져 있었다. 탐색 탭은 배경이 `colors.ink`(#171719)로 이미 다크였고
스플래시도 검정인데, 홈·여행·마이는 흰 배경이었다. 탭을 옮길 때마다 화면이
번쩍였다.

## 결정

**전체 지도를 라우트에서 내리고 탭 배경으로 올린다.** 지도는 여행 탭에 상시
떠 있고 대화는 `GlassSheet`(peek/half/full) 안에서 벌어진다. 시트를 내린 상태가
곧 전체 지도라 왕복 비용이 0이다. `/travel-map`·`TurnMap`·`TravelMapView` 를
지운다. 0012 가 정한 "전체 지도를 스택 라우트로 올린다"를 대체한다.

**기준점과 결과를 핀 색으로 가른다.** `KakaoWebMap` 에 `anchorId` 를 주면 기준점은
accent, 결과는 파랑이 된다. "섬에서 12km 떨어진 육지"가 문장이 아니라 그림으로
읽힌다.

**앱 전체를 다크로 옮긴다.** `colors` 토큰의 값만 바꿔 65개 파일 452곳을 그대로
둔다. `colors.ink` 를 배경으로 쓰던 자리처럼 의미가 뒤집히는 곳만 손본다.

**카카오 다크 지도는 CSS 반전으로 만든다.** 카카오 SDK 에 다크 basemap 이 없다.
타일을 `invert(1) hue-rotate(180deg)` 로 뒤집고 마커·라벨에 같은 필터를 다시 걸어
되돌린다. 겹친 핀(`.sel > .pin`)은 바깥에서만 되돌린다 — 안쪽까지 걸면 세 번
반전돼 색이 도로 어두워진다.

**네이티브 설정은 이 변경에 태우지 않는다.** `app.json` 의 `userInterfaceStyle` 을
건드리면 `runtimeVersion.policy: fingerprint` 가 바뀌어(실측 `dc0bdd62` → `c94041f1`)
`mobile-ota.yml` 이 기존 설치본을 조용히 건너뛴다. 상태바는 JS 로 잡고,
`userInterfaceStyle: "dark"` 는 다음 `v*` 태그 빌드에 함께 보낸다.

**제스처 라이브러리를 넣지 않는다.** 시트 드래그와 스와이프 해제는 RN 코어
`PanResponder` + `Animated` 로 만든다. 네이티브 모듈이 붙으면 같은 이유로 이 두
탭의 이후 JS 수정까지 OTA 로 못 나간다.

## 결과

- 카카오 다크는 실기기 검증 전이다. 어색하면 `KakaoWebMap` 의 `dark` 를 끄면
  지도만 라이트로 돌아간다 — 시트와 크롬은 그대로다.
- `/map` 은 남는다. 카테고리 칩·이 지역 검색·지역 선택기를 여행 탭이 아직
  갖지 않았다.
- 스크랩 목록이 60개에서 잘리는 제약은 그대로다. 이 변경은 잘린 값에 `+` 를
  붙여 숫자가 거짓말하지 않게만 했다. 커서를 끝까지 따라가는 일은 목록 전체가
  같은 제약을 공유하므로 따로 다룬다.
