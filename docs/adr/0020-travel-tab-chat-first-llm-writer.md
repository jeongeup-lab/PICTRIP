# 0020. 여행 탭을 채팅-first로 바꾸고 답변 작문을 LLM 스트리밍에 맡긴다

- 상태: 채택
- 날짜: 2026-08-11
- 관련: [travel-tab](../reference/travel-tab.md), [api](../reference/api.md),
  [0009 대화형 에이전트 전환](0009-travel-tab-conversational-agent.md),
  [0018 패널 하나로 합침](0018-travel-tab-answers-in-one-rising-panel.md)

## 맥락

여행 탭의 답변은 서버 템플릿 문장이다(`_lead_sentence` + 조건 나열). 카드와
지도는 정확하지만, 사용자가 기대하는 답 — 장소별 한줄 평, 휴무일·예약 같은
팁, "범위를 넓혀줄까" 같은 이어가기 — 은 템플릿으로 만들 수 없다. 같은 질문을
범용 챗봇(GPT·Claude 앱)에 넣으면 산문 품질에서 비교가 되지 않는 것을
스크린샷 대조로 확인했다.

품질 격차의 원인은 검색이 아니라 **작문**이다. 결정적 조회는 이미 옳은 스팟을
찾는다. 그 결과를 문장으로 엮는 단계만 사람이 쓴 것 같은 층위가 필요하다.

두 가지 부수 격차도 확인했다:

- **신뢰 신호** — 범용 챗봇은 별점·리뷰수를 보여준다. 우리는 합법적 별점
  소스가 없다(Google Places는 ToS상 Google 지도 위에만 표시 가능, 다이닝코드·
  식신 스크래핑은 약관 위반). 대신 이미 가진 집중률과 네이버 블로그 검색
  근거가 있다.
- **표면** — 마지막 턴 하나만 남는 패널([0018](0018-travel-tab-answers-in-one-rising-panel.md))은
  이어지는 대화를 표현할 수 없다.

## 결정

**검색은 결정적으로 유지하고, 작문만 Gemini Flash 스트리밍에 맡긴다.**

- 새 진입점 `POST /agent/chat` (SSE). 흐름: 기존 `ask` 파이프라인(의도 추출 +
  결정적 조회) → 네이버 블로그 그라운딩(≤4콜, 실패 무해) → 라이터가 산문을
  스트리밍. 라이터는 도구 결과에 있는 사실만 쓰고, 장소는 서버가 검증한
  카드로만 노출한다(`[[cards]]` 위치 마커).
- **SSE를 도입한다** — [0009](0009-travel-tab-conversational-agent.md)의 재검토
  조건(체감 3초 초과) 충족. 라이터 스트림은 그 자체로 수 초라 단일 JSON로는
  빈 화면이 길어진다. SSE 응답은 JSend 봉투의 예외다(스트림 시작 전 오류는
  기존 AppError/JSend).
- **화면은 채팅 트랜스크립트가 표면이다.** 풀블리드 지도 + 패널
  ([0017](0017-travel-tab-drops-the-sheet-for-a-map-carousel.md) ·
  [0018](0018-travel-tab-answers-in-one-rising-panel.md))을 폐기하고, 지도는
  최신 턴 안의 인라인 카드로 들어간다. 멀티턴 문맥은 클라이언트가 요약
  `history`로 실어 보낸다(서버 무상태 유지).
- **별점은 만들지 않는다.** 카드 신호는 집중률·거리·(있을 때만) 영업정보,
  근거는 블로그 출처 배지 + 원문 링크 시트가 맡는다.
- `/agent/ask`는 구 OTA 클라이언트용으로 존치하고, OTA가 다 깔리면 지운다.

## 고려한 대안

- **LLM 오픈 툴콜 루프** — 품질 상한은 높지만 호출 수·지연이 예측 불가.
  0009의 기각 사유가 여전히 유효하다. 결정적 조회 + 작문 분리로 같은 체감
  품질을 유계 지연으로 얻는다. 기각.
- **Google Places로 별점 표시** — ToS가 Places 데이터를 Google 지도 위에만
  허용한다. 우리는 카카오 지도라 표시 자체가 위반. 기각.
- **Apple Foundation Models(온디바이스)** — 무료·오프라인이지만 ~3B 모델 +
  4k 컨텍스트로 도구 결과를 실어 장문 한국어 산문을 쓰기엔 부족하고, iPhone
  15 Pro 미만은 못 쓴다. 기각.
- **템플릿 고도화(현행 유지)** — 팁·이어가기·시간대 인지를 규칙으로 다 만들 수
  없다. 기각.

## 결과

- 백엔드: `agent/services/chat.py`(오케스트레이터) · `services/writer.py`
  (프롬프트 + 마커 파서) · `llm.py` 스트리밍 · `naver.py` 블로그 검색 추가.
- 모바일: `features/travel`을 트랜스크립트 구조로 재작성. 패널·독 칩
  상태기계·화면 높이 계산 등 0017/0018 산물은 삭제.
- 라이터 환각 방어: 스팟 목록에 없는 장소명·영업시간·전화 언급 금지를
  프롬프트로 강제하고, 카드는 서버 데이터로만 조립한다.
- 블로그 호출은 네이버 검색 API 무료 쿼터 내(콜당 timeout 2.5s). KTO 실시간
  호출은 기존대로 금지.
- 공모전 서사는 유지된다 — 조회·카드·집중률·축제는 전부 KTO OpenAPI가 소스고,
  네이버·카카오는 보조 근거다.
