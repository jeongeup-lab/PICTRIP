# 0008. 문서는 Diátaxis 4분류 docs-as-code

- 상태: 채택
- 날짜: 2026-07-17
- 관련: [README](../README.md)

## 맥락
설계 세션 산출물(스펙 16·플랜 7, ~8,400줄)이 문서의 95%를 차지했고 대부분
현행과 어긋난 히스토리였다. 1차 정리에서 "현행 문서 4종"(product·architecture·
operations·decisions)으로 압축했으나, 단일 파일이 이해·작업·조회 목적을 섞어
찾기 어려웠다.

## 결정
**[Diátaxis](https://diataxis.fr) 4분류로 재편한다**: explanation(이해) ·
how-to(작업) · reference(찾아보기) · adr(결정 이력). 템플릿은 제목 → `>` 한 줄
목적문 → 타입별 섹션 → `---` 관련 링크. 원칙 셋 — 현행만 기록한다 / 코드로 알
수 있는 것은 쓰지 않는다 / 문서당 하나의 질문에 답한다. ADR은 `NNNN-제목.md`
순차, 파일당 1결정, 채택 후 본문 불변(뒤집으면 새 ADR로 대체).

## 고려한 대안
- **단일 파일 4종 유지** — 파일 수는 적으나 목적 혼합으로 탐색성 열위. 기각.
- **위키/노션 외부화** — 코드와 함께 버전관리되지 않아 드리프트. 기각.

## 결과
- 구 4종은 이 구조로 분해·이관. 삭제된 결정 로그의 잔여 항목은 각 explanation의
  "설계 근거" 섹션과 ADR 0001–0007이 수용한다.
- 구 설계 스펙(S00–S13)·플랜·결정 로그 전문은 git 히스토리에 보존.
