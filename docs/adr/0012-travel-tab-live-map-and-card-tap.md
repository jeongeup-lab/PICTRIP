# 0012. 여행 탭에 실제 지도를 들이고, 카드 탭을 앵커로 되돌린다

- 상태: 일부 대체 — 전체 지도 라우트는
  [0015](0015-travel-and-profile-go-dark-on-one-map.md) 가 상시 지도로 바꿨고,
  `카드 한 번 탭 = 앵커, 두 번 탭 = 상세` 는
  [0017](0017-travel-tab-drops-the-sheet-for-a-map-carousel.md) 이 폐기했다
- 날짜: 2026-08-06
- 관련: [travel-tab](../reference/travel-tab.md), [api](../reference/api.md),
  [0009 여행 탭 대화형 에이전트](0009-travel-tab-conversational-agent.md),
  [0010 조건 시트 폐기](0010-travel-tab-drops-condition-sheet.md),
  [0011 칩 상태 기계](0011-travel-tab-chip-state-machine.md),
  [0017 시트를 버리고 지도 위 캐러셀로](0017-travel-tab-drops-the-sheet-for-a-map-carousel.md)

## 맥락

여행 탭을 실제로 써 보고 나온 문제 다섯 가지다. 넷은 앞선 ADR이 내린 결정을
뒤집는다.

- **턴 안의 지도가 지도로 안 보인다.** 0009는 WebView N개를 피하려고 좌표를
  정규화한 정적 SVG 프리뷰를 뒀다. 그 결과 회색 배경에 점 몇 개라 "지도"로
  읽히지 않고, 결과가 실제로 어디에 흩어져 있는지도 안 보인다.
- **지도에서 상세로 갔다가 뒤로 오면 대화다.** 지도가 RN `Modal` 이라 상세로
  가려면 모달을 먼저 닫아야 했다. 스택에는 대화만 남아 뒤로 가기가 지도를
  건너뛴다.
- **지도 상단이 첫 프레임에 잘린다.** 같은 모달 안의 `SafeAreaView` 가 첫
  프레임에 인셋 0을 줘서 닫기 버튼과 질문 줄이 노치 밑으로 들어간다.
- **`여기 기준으로` 버튼이 카드값을 못 한다.** 0009는 "탭 하나에 두 뜻을 싣지
  않는다"며 앵커를 전용 버튼으로 뺐다. 실제로는 이어 묻기가 상세보다 잦은
  동작인데 34px 줄이라 표적이 더 작고, 카드마다 그 줄이 붙어 레일이 무겁다.
- **`조건 하나 풀기`류 칩이 무엇을 하는지 알 수 없다.** 0010이 만든 완화 칩은
  서버가 고른 축 하나를 푸는데, 라벨만 봐서는 무엇이 사라지는지 모른다.

## 결정

**대화 화면이 지도와 카드를 그대로 다루게 하고, 조건은 말로 바꾼다.**

- **턴 지도를 실제 `KakaoWebMap` 으로 바꾸되, 살아 있는 지도는 하나다.** 좌표가
  있는 **가장 최근 턴만** 지도를 마운트한다. 지나간 턴은 같은 카드에서 요약 줄과
  `지도에서 보기` 만 남는다. 지도는 비대화형(`interactive={false}`) 이고
  컨테이너가 `pointerEvents="none"` 이라 대화 스크롤을 가로채지 않는다.
- **턴 지도의 핀은 빨강이다.** 이 지도에 있는 것은 전부 방금 찾은 결과라
  카테고리 잉크 핀과 구분할 필요가 없다. 카드를 탭해 앵커를 잡으면 그 핀이
  라벨 달린 큰 핀이 되고 지도가 그 좌표로 옮겨 간다.
- **전국에 흩어진 결과는 가장 많은 지역만 프레이밍한다.** 200px 지도가 Kakao
  최소 축척에서 담는 세로 폭은 약 300km 다. 실측에서 고성~제주(위도 5.1°)를
  전부 맞추려다 **핀이 하나도 안 보이는 빈 지도**가 나왔다. 위도 폭 2.5°를
  넘으면 가장 많은 `regionLabel` 묶음에 맞추고, 핀은 전부 올린다.
- **전체 지도를 모달에서 스택 라우트(`/travel-map`)로 올린다.** 뒤로 가기가
  대화 → 지도 → 상세를 그대로 되짚고, 인셋은 `useSafeAreaInsets()` 로 첫
  프레임부터 정확하다. 실을 데이터는 `travel/stores/map-store.ts` 가 든다.
- **카드 한 번 탭 = 앵커, 두 번 탭 = 상세.** 판정은 `useCardTap`(260ms). 전용
  앵커 버튼과 34px 줄을 지운다(카드 168×224 → 168×190).
- **조건 완화 칩을 없앤다.** 결과 턴의 `refinements` 는 축을 **켜는** 칩만 담고,
  0곳 턴에는 `지역 넓히기` 한 장만 남는다. 0곳 답변 문구도 "조건 하나를 풀면"
  에서 "조건을 조금 바꿔서 다시 물어봐 주세요" 로 바꾼다.
- **빈 화면의 `사진으로 찾기` CTA 를 지우고 워드마크를 가운데로 둔다.**

## 고려한 대안

- **모든 턴에 지도를 마운트** — 일관되지만 대화 10턴이면 WKWebView 10개 +
  Kakao SDK 10회 로드다. 사용자는 항상 마지막 턴을 보고 있으므로 최신 턴 하나로
  같은 체감을 얻는다. 기각.
- **지도 카드를 스크롤 안에서 조작 가능하게** — 세로 스크롤과 지도 팬이 같은
  제스처라 둘 중 하나가 반드시 진다. 탭하면 전체 지도가 열리므로 미니 지도는
  보여 주기만 한다. 기각.
- **모달을 유지하고 상세를 모달 위에 다시 모달로** — 인셋 문제가 그대로 남고,
  뒤로 가기 스택이 두 겹이 된다. 기각.
- **길게 누르기로 상세** — 탭 두 번보다 배우기 어렵고, 레일에서 롱프레스는
  스크롤 시작과 충돌한다. 기각.
- **완화 칩 문구만 고치기**(`실내 빼고 다시` 등) — 라벨을 고쳐도 "서버가 고른
  축 하나"라는 성질은 그대로다. 조건을 바꾸는 말은 이미 자유문으로 된다. 기각.

## 결과

**0009의 "턴 안의 지도는 WebView 가 아니다" 와 "앵커는 전용 버튼이다" 는 폐기된다.**
[travel-tab](../reference/travel-tab.md) 이 현행이다.

**0곳 턴의 탈출구가 `지역 넓히기` 하나로 줄어든다.** 지역 힌트가 없으면 칩이
없다 — 조건을 되짚는 답변 문장만 남는다. 되짚을 조건조차 없는 요청(조건 없는
사진 질의)은 이전처럼 `AGENT_NO_RESULTS` 다.

**칩에서 `patch.drop` 을 쓰는 경로는 `지역 넓히기` 만 남는다.** `RefinePatch.drop`
과 `refine.drop_leaves_named_place_only` 는 그대로 둔다 — 축을 푸는 요청은
여전히 API 계약이고, 지역 칩이 그 경로를 쓴다.
